Python API#

Every CrystOD analysis is also available as a Python function, so that a part of CrystOD can be used inside another program without going through the command line. The API mirrors the command structure: one module per command, with the same vocabulary (irreps, q points, order parameters) as the printed output.

import crystod

crystod.salc      # crystal-orbital SALC analysis   (crystod)
crystod.group     # irreps, isotropy subgroups      (crystod-group)
crystod.phonon    # phonon irreps, modes, subgroups (crystod-phonon)
crystod.bz        # Brillouin zones, k paths        (crystod-bz)
crystod.mag       # symmetry-adapted spin bases     (crystod-mag)
crystod.md        # MD-trajectory analyses          (crystod-md)
crystod.mol       # molecular SALCs, MO diagrams    (crystod-mol)
crystod.xrd       # powder XRD patterns             (crystod-xrd)
crystod.search    # Materials Project search        (crystod-search)

Testsuite section 45 checks everything documented on this page, apart from the keywords and checks of Library use: keywords and input checks, which the sections of their commands test (named there), and the packaged examples, whose command section 50 tests.

Note

Importing CrystOD is cheap: import crystod and the nine domain modules pull in nothing heavier than NumPy. phonopy, spgrep, spglib, PySCF and matplotlib are imported only when a function that needs them is actually called, so a program that uses one corner of CrystOD does not pay for the rest.

Isotropy subgroups of an irrep#

crystod.group.isotropy_subgroups is the API form of crystod-group --parent: given a space group and one of its irreps, it enumerates the order-parameter directions and the subgroup each of them condenses into.

from crystod.group import isotropy_subgroups

for sub in isotropy_subgroups("Pm-3m", "R4+"):
    print(sub.label, "->", sub.number, sub.symbol, "size", sub.size, "index", sub.index)

R4+(0,0,a) -> 140 I4/mcm size 2 index 6
R4+(a,a,a) -> 167 R-3c size 2 index 8
R4+(0,a,a) -> 74 Imma size 2 index 12
R4+(0,a,b) -> 12 C2/m size 2 index 24
R4+(a,a,b) -> 15 C2/c size 2 index 24
R4+(a,b,c) -> 2 P-1 size 2 index 48

The space group is given as a symbol or a number (221 works as well), and a list of labels enumerates the subgroups of coupled order parameters, exactly as --irrep X3- X2+ does on the command line.

crystod.group.isotropy_subgroups_at_kpoint does the same for every irrep of one special k point — the API form of crystod-group --parent SG --kpoint K. It returns a dict from irrep label to the list isotropy_subgroups gives for that irrep, in the order of the ISO-IR tables:

from crystod.group import isotropy_subgroups_at_kpoint

table = isotropy_subgroups_at_kpoint("Pm-3m", "GM")
list(table)       # ['GM1+', 'GM2+', 'GM3+', 'GM4+', 'GM5+', 'GM1-', 'GM2-', 'GM3-', 'GM4-', 'GM5-']
for sub in table["GM3+"]:
    print(sub.label, "->", sub.number, sub.symbol, "size", sub.size, "index", sub.index)

GM3+(a,0) -> 123 P4/mmm size 1 index 3
GM3+(a,b) -> 47 Pmmm size 1 index 6

The k point is its ISO-IR name or three coordinates in the primitive reciprocal basis; any arm of the star and any equivalent q + G are recognized (isotropy_subgroups_at_kpoint(221, [0, 0.5, 0.5]).kpoint is 'M'). The returned KpointIsotropySubgroups is a plain dict with a few attributes: kpoint, coordinates (the tabulated arm), n_arms, space_group, space_group_number, and errors. An irrep whose enumeration fails does not stop the others: it is left out of the mapping and named in errors ({label: reason}, empty on success). The two members of a complex-conjugate pair share one physically irreducible order parameter and appear once, under their pair label (GM2+GM3+ of Pm-3); the records are those of the first member (isotropy_subgroups("Pm-3", "GM2+")), and their direction components refer to the basis built from it. An unknown k-point name, or coordinates that are not a tabulated special point, raise ValueError with the k points of the space group in the message.

Bad input raises ValueError — an unknown space group, an invalid order parameter, or an irrep that is not tabulated for that space group. The last case is worth catching: the labels of symmetry lines and planes (DT5, LD3, SM1, …) are legitimate mode labels, but only the maximal k points have isotropy subgroups in the tables.

Note

Every function of every API domain reports bad input as ValueError. The implementation modules double as command-line entry points and raise SystemExit instead, which a caller’s except Exception would not catch — the API namespaces translate that at their boundary. The classes they expose (IsotropyAnalyzer, SpaceGroupIrrepAlgebra, MODiagram, …) are the implementation classes themselves, so that isinstance and dataclass equality keep working; their constructors still raise SystemExit on bad input. Prefer the functions, and construct the classes from values you have already validated. crystod.search raises one more exception, search.MaterialsProjectError (a RuntimeError), when the Materials Project cannot answer: no or a rejected API key, no network, or an error reported by the server.

try:
    subs = isotropy_subgroups(221, mode.labels[0])
except ValueError as exc:
    print("no subgroups for this level:", exc)

order_parameter takes plain numbers and parameter names (["0", "0", "a"]). Hexagonal and trigonal irreps also have strata whose enumerated direction carries a coefficient — K3(0.282a;a) of P6_3/mmc, for instance. Those entries can be read from the enumeration but not resolved from components, so passing them back raises ValueError instead of quietly returning the subgroup of a different, more generic direction.

Each entry is an IsotropySubgroup with the fields irrep, direction, label, number, symbol, size, index, n_free, and — for a single direction — the conventional basis and origin of the subgroup cell in the parent convention:

sub = isotropy_subgroups(221, "R4+", order_parameter=["0", "0", "a"])[0]

sub.symbol      # 'I4/mcm'
sub.basis       # array([[-1., 0., 1.], [1., 0., 1.], [0., 2., 0.]])
sub.origin      # array([0., 0., 0.])

Phonon modes and their irreps#

crystod.phonon.label_phonon_modes labels the modes of a live phonopy object with ISO-IR irreps — the machinery behind crystod-phonon --irreps, without the YAML file:

import phonopy
from crystod.phonon import label_phonon_modes

ph = phonopy.load(supercell_matrix=[4, 4, 4], primitive_matrix="auto",
                  unitcell_filename="221_PPOSCAR_SrTiO3",
                  force_sets_filename="FORCE_SETS")

for mode in label_phonon_modes(ph, [0.5, 0.5, 0.5]):
    print(mode)

modes 1,2,3: -1.0867 THz  R5-
modes 4,5,6: 3.9891 THz  R4-
modes 7,8,9: 11.6887 THz  R5+
modes 10,11,12: 12.6621 THz  R4-
modes 13,14: 14.8133 THz  R3-
modes 15: 23.2302 THz  R2-

Each PhononMode carries band_indices (1-based, as in every CrystOD output), frequency in THz, the irrep labels, the qpoint, the name of its star (qpoint_label), degeneracy, and is_imaginary. A q point given as a non-representative arm of a star is mapped onto the tabulated arm automatically, so [-0.5, 0.5, 0.5] is labeled R just like [0.5, 0.5, 0.5].

Note

Build the phonopy object with primitive_matrix="auto". With an identity primitive matrix, a zone-boundary instability of a supercell calculation is folded onto the supercell Gamma point, where it cannot be labeled with an irrep of the parent space group.

From imaginary phonons to subgroups#

Combining the two — labeling an imaginary mode and enumerating the isotropy subgroups of its irrep — is the symmetry-lowering step of a structure search. crystod.phonon.imaginary_mode_subgroups does it in one call:

from crystod.phonon import imaginary_mode_subgroups

for result in imaginary_mode_subgroups(ph, [0.5, 0.5, 0.5]):
    mode = result.mode
    print(f"{mode.frequency:.4f} THz  {'+'.join(mode.labels)}  "
          f"(degeneracy {mode.degeneracy})")
    for sub in result.subgroups:
        print("   ", sub.label, "->", sub.symbol)

-1.0867 THz  R5-  (degeneracy 3)
    R5-(0,0,a) -> I4/mcm
    R5-(a,a,a) -> R-3c
    R5-(0,a,a) -> Imma
    R5-(0,a,b) -> C2/m
    R5-(a,a,b) -> C2/c
    R5-(a,b,c) -> P-1

Every order-parameter direction of the degenerate level is covered, including the ones a single frozen-in modulation would miss: freezing in one eigenvector of the R-point triplet of SrTiO3 gives I4/mcm, but the same triplet also reaches R-3c and Imma, which are the tilt systems a structure search has to try before it can claim a ground state.

scan_imaginary_modes runs the same analysis over every q point the supercell resolves, so no q point has to be guessed:

from crystod.phonon import scan_imaginary_modes, commensurate_qpoints

len(commensurate_qpoints(ph))          # 64 for a 4x4x4 supercell
results = scan_imaginary_modes(ph)     # most unstable level first

Arms of the same star are analyzed once, q points that cannot be labeled are skipped with a warning instead of aborting the scan, and threshold (default -0.1 THz) sets what counts as imaginary. A level whose irrep has no tabulated subgroups (a symmetry line or plane) comes back with an empty subgroups and the reason in errors, so a scan never dies part-way through:

for result in scan_imaginary_modes(ph):
    if result.errors:
        print(result.mode, "->", result.errors)

See also

The same analysis is available from the command line as crystod-phonon --subgroup, and the theory behind the enumeration is described in Isotropy subgroups.

Magnetic groups, MD projection and superlattice reflections#

The functions behind crystod-mag --qpoint / --classify-only, crystod-md --project, crystod-xrd --parent and the axis settings and transformation block of crystod-group added in v0.4.4. The block runs as written from the top of the CrystOD source tree, with the shipped example files as inputs, or after pip install in a directory where crystod-example 40 28 has copied the examples into ./example (40 brings 33_modulation along) and crystod-phonon --irreps --dim 4 4 4 -c 221_PPOSCAR_SrTiO3 has been run in example/28_phonon_irrep/SrTiO3_Pm-3m: phonon_irreps.yaml is an output of that command, not a packaged file. crystod.mag takes the crystal as a phonopy PhonopyAtoms (atoms), the space-group functions of crystod.group as the spglib tuple (lattice, positions, numbers) (spg_cell):

import numpy as np
import phonopy
from phonopy.interface.vasp import read_vasp
from pymatgen.core import Structure
from crystod import group, mag, md, phonon, xrd

# inputs: shipped example files, paths from the top of the source tree (or of
# the directory holding the ./example that crystod-example writes)
atoms = read_vasp("example/test_POSCARs/136_PPOSCAR_TiO2")    # PhonopyAtoms (crystod-mag)
spg_cell = (atoms.cell, atoms.scaled_positions, atoms.numbers)  # spglib tuple (crystod-group)
magmoms = np.zeros((len(atoms.numbers), 3))
magmoms[atoms.numbers == 22] = [[0, 0, 1], [0, 0, -1]]          # antiparallel Ti
symbols, lattices, frames = md.read_xdatcar("example/40_md_projection/XDATCAR_I4mcm_1")
phonon_obj = phonopy.load("example/33_modulation/ScF3_Pm-3m/phonopy_params.yaml", is_nac=False)
parent_cif = "example/test_POSCARs/221_PPOSCAR_SrTiO3.cif"
child_cif = "example/test_POSCARs/140_PPOSCAR_SrTiO3.cif"
structure = Structure.from_file(child_cif)

mag.analyze_spin_basis(atoms, "Ti", "GM")               # SpinBasisAnalysis, section 37
mag.magnetic_summary_rows, mag.magnetic_summary_notes   # the summary table, section 37
info = mag.magnetic_space_group(*spg_cell, magmoms)     # MagneticGroupInfo, section 37
mag.macroscopic_responses(info)                         # MagneticResponses, section 37
mag.classify_collinear, mag.magnetic_point_group_symbol # CollinearClass, MPG symbol, section 37
md.project_trajectory("example/test_POSCARs/221_PPOSCAR_ScF3", (2, 2, 2),
                      symbols, lattices, frames, qpoints=["R", "M"])  # TrajectoryProjection, section 40
md.project_trajectory(None, (2, 2, 2), symbols, lattices, frames,
                      phonon=phonon_obj, temperature=300)  # phonon-eigenvector basis, section 40
md.format_projection, md.commensurate_qpoints           # section 40
xrd.superlattice_reflections(parent_cif, child_cif)     # SuperlatticePattern, section 47
xrd.format_superlattice_pattern, xrd.write_superlattice_table  # section 47
xrd.plot_superlattice_pattern, xrd.radiation_lines      # section 47
xrd.compute_xrd_pattern(structure, radiation="neutron", wavelength=1.5)  # XRDPattern, section 47
group.list_space_group_settings(spg_cell)               # SettingTable, section 22
group.resolve_setting, group.transform_to_setting       # SpaceGroupSetting, its cell, section 22
group.SymmetryModeAnalysis(
    parent_cif, child_cif, 0.01).setting_transformation()  # SettingTransformation (P, p), section 23
phonon.read_phonon_irreps(   # the output of crystod-phonon --irreps in that directory
    "example/28_phonon_irrep/SrTiO3_Pm-3m/phonon_irreps.yaml")  # dict, section 28

The records these return are mag.SpinBasisAnalysis, mag.SpinBasisComponent, mag.MagneticGroupInfo, mag.MagneticResponses and mag.CollinearClass (with mag.format_magnetic_responses for their printed form), md.TrajectoryProjection, xrd.SuperlatticePattern, xrd.SuperlatticeReflection and xrd.KPointSummary, and group.SettingTable and group.SpaceGroupSetting; xrd.RADIATIONS lists the radiations. See crystod-mag section 37, crystod-md section 40, crystod-xrd section 47, crystod-group sections 22 and 23 and crystod-phonon section 28 for the arguments and the printed forms.

Band irreps of a VASP run#

crystod.salc.extract_band_irreps is crystod --extract-irrep (section 49): the irreps of the electronic bands of one finished VASP run, read straight from its WAVECAR. The block runs as written from the top of the CrystOD source tree, on the small SrTiO3 and InP runs shipped as test inputs. After pip install, crystod-example 03 copies the SrTiO3 and InP_SOC runs into ./example/03_hybridization/vasp_wavecar, and the block runs there too, except the SrTiO3_ISPIN2 lines: that run is not in the pip package.

from crystod.salc import extract_band_irreps, format_band_irreps, write_band_irreps_yaml

result = extract_band_irreps("example/03_hybridization/vasp_wavecar/SrTiO3")
[k.label for k in result.kpoints]   # ['GM', 'R', 'X', 'M']: the special points in the file
gm = result.kpoint("GM")            # a KPointIrreps: label, kpoint, index, little_group, levels
[(lv.bands, lv.irrep, lv.mulliken) for lv in gm.levels[4:9]]
# [([8, 9, 10], 'GM4-', 'T1u'), ([11, 12, 13], 'GM5-', 'T2u'), ([14, 15, 16], 'GM4-', 'T1u'),
#  ([17, 18, 19], 'GM5+', 'T2g'), ([20, 21], 'GM3+', 'Eg')]
round(result.gap, 4)                # 1.8051 (eV): CBM - VBM over every k point of the file
result.kpoint("M").levels[-1].note  # 'incomplete: the band list ends inside this multiplet ...'

x = extract_band_irreps("example/03_hybridization/vasp_wavecar/SrTiO3",
                        kpoints=["X", "1/4 1/4 1/4"], zero="efermi", window=(-3, 2))
[(k.label, k.little_group, [lv.irrep for lv in k.levels]) for k in x.kpoints]
# [('X', 'P4/mmm (123)', ['X3-', 'X5+', 'X4-', 'X5-', 'X4+']), ('LD', 'R3m (160)', ['LD3', 'LD2'])]

# not in the pip package: the ISPIN = 2 run stays in the CrystOD development tree
spin = extract_band_irreps("example/03_hybridization/vasp_wavecar/SrTiO3_ISPIN2",
                           kpoints=["X"], spin="up")
[(k.label, k.spin) for k in spin.kpoints], spin.metallic   # ([('X', 'up')], True)

inp = extract_band_irreps("example/03_hybridization/vasp_wavecar/InP_SOC", kpoints=["L"])
pair = inp.kpoint("L").levels[3]     # zincblende InP with spin-orbit coupling
pair.bands, pair.irrep, pair.note    # ([7, 8], '-L4/-L5', 'time-reversal pair (-L4 + -L5)')
pair.parts                           # [([7], '-L5'), ([8], '-L4')]: the irrep of each band

lines = format_band_irreps(result)                # the terminal report, line by line
write_band_irreps_yaml(result, "band_irreps.yaml")  # the -o file; result.to_dict() is its content

The arguments are those of the command: path (the WAVECAR or the run directory), kpoints (None for every special point the file holds, "all" for every k point, or a list of labels and coordinates — "X", [0, 0.5, 0], "0 1/2 0"), zero ("vbm", "efermi", "raw"), window ((emin, emax) in eV relative to the zero), spin ("up", "down", "both"), symprec, degeneracy_tol (eV, default 0.001) and the keyword cell (the -c file). The result is a BandIrreps dataclass: the run facts (nbands, nkpts, ispin, spinor, encut, efermi and efermi_source, vbm, cbm, metallic, gap), the space group, the analysed kpoints (KPointIrreps, one per k point and spin channel) with their levels (BandLevel: level, 1-based bands, energy relative to the zero, energy_raw, degeneracy, irrep, mulliken, note, occupation, irreps, multiplicities, and parts: the irrep of each band when the bands of an A/B level are pure states) and the edges (BandEdges per k point). Bad input — no WAVECAR, no POSCAR, a k point the file lacks, an unreadable WAVECAR — raises ValueError with the message the command prints. The sublattice runs of crystod --diagram --vasp-setup (Va point charges in the POSCAR) are read like any other run.

The packaged examples#

crystod.examples holds the inputs of the --example options and the example directories that crystod-example copies (section 50); the functions behind that command are these:

from crystod.examples import (ExampleConflictError, copy_example_dirs, example_dir_path,
                              get_example_dir, list_example_dirs, resolve_example_dirs)

len(list_example_dirs())           # 41 packaged directories (ExampleDirectory records)
ex = get_example_dir(29)           # by number or name ("29_phonon_activity")
ex.requires                        # ('28_phonon_irrep', '30_phonon_fatband'): its README uses them
example_dir_path(29)               # the directory inside the installed package
[d.name for d in resolve_example_dirs([29])]
# ['29_phonon_activity', '28_phonon_irrep', '30_phonon_fatband']

try:
    paths = copy_example_dirs([29], "work")   # = crystod-example 29 -o work
except ExampleConflictError as exc:            # a file in work/ differs; nothing written
    print(exc.paths)

copy_example_dirs copies the directories and the ones their READMEs use, plus the shared test_POSCARs/ and test_XYZs/, keeps files that are already there and identical, and refuses with ExampleConflictError (a FileExistsError) before writing anything if one differs. Run the README commands in the copy, not inside the package: they write their outputs next to their inputs. See crystod-example for the details.

The implementation modules (crystod.phonon_irreps, crystod.isotropy_subgroup, crystod.operations, …) remain importable under their own names, so code written against CrystOD before the API modules existed keeps working unchanged; the domain modules are a curated, stable view over them.

Library use: keywords and input checks#

A few keywords and checks matter when CrystOD runs inside another program. The block runs as written from the top of the CrystOD source tree, or next to the ./example that any crystod-example NN writes (it reads one of the shared structures):

import numpy as np
from phonopy.interface.vasp import read_vasp
from crystod import bz, group, phonon
from crystod.decompose_irrep import representation_problem

cell = read_vasp("example/test_POSCARs/221_PPOSCAR_ScF3")
phonon.SymmetryOnlyVibrations(cell, quiet=True)     # no primitive-cell note on stdout

sg_type, names, primitive, conventional = bz.get_special_kpoints("Pbnm")
sg_type.international_short     # 'Pnma': the setting the coordinates refer to
conventional                    # None: a primitive lattice

rec_lat = np.linalg.inv(cell.cell).T
vertices, ridges, facets = bz.get_brillouin_zone_3d(rec_lat, tolerance=1e-5)
bz.get_folded_gamma_points(np.diag([2, 1, 1]), rec_lat)   # 2 q points; np.diag([1.5, 1, 1]) raises ValueError

table = group.get_character_table("3m")
group.decompose([2, 0, 1], table)           # {'A1': 1, 'A2': 0, 'E': 1}: rounded, not checked
representation_problem([2, 0, 1], table)    # 'the reduction formula gives non-integer multiplicities ...'
representation_problem([0, 0, 2], table)    # 'negative multiplicities A2 -1 (a difference of representations)'
representation_problem([3, 0, 1], table)    # None: the character of A1 + E

  • phonon.SymmetryOnlyVibrations(cell, quiet=True) does not print the note ### Inputed cell was converted into primitive cell. ### when it reduces cell to the primitive cell (default quiet=False, which the commands keep). phonon.gamma_mode_activities passes it, so neither a library call nor the crystod_phonon_activity MCP tool prints the note (section 34).

  • bz.get_special_kpoints returns as its first element the spglib record of the ISO-IR standard setting of the group, the setting the coordinates refer to. A non-standard setting symbol selects the group only: Pbnm gives the table of Pnma, Amam and Bbmm that of Cmcm with its C-centred coordinates. The conventional coordinates are None for a primitive lattice (section 27).

  • bz.get_brillouin_zone_3d(rec_lat, tolerance=1e-5) merges zone corners closer than tolerance times the length of the shortest reciprocal lattice vector and drops faces left with fewer than three corners, so a cell that is cubic up to noise gives the cube; tolerance=0 keeps every corner. The zone is built on the Selling-reduced basis, so any basis of the lattice gives the same polyhedron (section 25).

  • bz.get_folded_gamma_points and bz.parse_transformation_matrix raise ValueError for a transformation matrix with a non-integer entry, which describes no supercell (parse_transformation_matrix accepts a fraction equal to an integer, such as 4/2). The folded points are the nearest images also for oblique unit-cell bases (section 26).

  • group.decompose rounds the reduction formula and does not check its input; since v0.4.4 crystod-group --decompose refuses a vector that is not the character of a representation. The check is crystod.decompose_irrep.representation_problem(characters, table), which crystod.group does not export: it returns None for the character of a representation, and otherwise a sentence naming what is wrong. It names the non-integer multiplicities of the reduction formula, the negative ones ([0, 0, 2] in 3m is A1 - A2: negative multiplicities A2 -1 (a difference of representations)), and, when the rounded combination does not give the vector back, that combination and its characters ([2, 0, 1]: the nearest integer combination 1(A1) + 1(E) has the characters 3 0 1, not 2 0 1) (section 10).
