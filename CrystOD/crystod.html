crystod (main command)#

The main command performs the SALC (symmetry-adapted linear combination) analysis of crystal orbitals — no mode flag is needed. It also hosts the crystal-orbital diagram (--diagram, with the band structure and DOS of the same calculation), the interactive SALC viewer (--visualize), the star-of-k display (--star-of-k), the band irreps of a finished VASP run (--extract-irrep), the unfolding of the bands of a low-symmetry VASP run onto the Brillouin zone of its high-symmetry parent run (--unfold) and the check of the response tensors of a VASP run against the symmetry of its structure (--check-symmetry).

Note

The example/... paths on this page are those of a clone of the repository, used from its root. After pip install CrystOD, run crystod-example NN (the number of the example directory) in your working directory first: it copies that directory and the shared test_POSCARs/ into ./example/, and the commands then run from there unchanged (see crystod-example).

How to read the output.

  • k point (primitive): the label of the special k point and its coordinates in the primitive reciprocal basis. When --kpoint is omitted, all special k points of the space group are analyzed.

  • little group of k: the space-group type of the little group of k.

  • irreps: each irrep with its multiplicity and, in parentheses, its dimension (1.0 [GM3+(2)]: GM3+ once, two-dimensional).

  • The labels are ISO-IR labels and refer to one frame per structure: an input in the ISO-IR setting keeps its own axes and origin (with Sr or Ti at the origin of SrTiO3 the octahedral tilt is R5- or R4+), and so does a diagonal n1 x n2 x n3 supercell of it of any size, which is labelled like the cell; any other input gets a canonical frame of the crystal, which keeps the input’s own origin when that is the origin of a standard description. Compare labels between inputs given in the same setting. Any arm of a star and any copy k + G of a k point get the same labels; symmetry lines, the -k partners (PA, LE, DU) and the seekpath names that --visualize --kpoint and --star-of-k take are described in Irrep labels and the frame of a structure.

  • The atoms of an element need not be contiguous in the POSCAR. A file whose species blocks repeat, such as SrTiO3 written as O Ti O Sr O / 1 1 1 1 1, gives the same output as the same crystal written as Sr Ti O / 1 1 3: the analysis takes exactly the atoms of the element, wherever they stand in the file. The survey --element O --orbital p prints O (3) under * Element (number of atoms) *, the Wyckoff letters ['c', 'c', 'c'] and, at X, the 9-dimensional O p decomposition 1.0 [X1+(1)] + 1.0 [X2+(1)] + 1.0 [X3-(1)] + 2.0 [X5+(2)] + 1.0 [X5-(2)]; with --kpoint X the species line reads O_p (3) under * Orbital (number of atoms) *, as for the contiguous file. The same holds for --atomic-orbital and --visualize, where the atom labels of the coefficient lines follow the order of the file.

Options

Options.

  • --kpoint K: one k point, a label or coordinates. A name given to --kpoint is resolved in the frame of the labels, and given coordinates are named by the same labeller, so a printed name has the letters of the labels below it, also for an input outside the ISO-IR setting.

  • --show-irrep-table additionally prints the little-group character table at the selected k point (with --kpoint; the survey over all special points prints no table). It also writes that table to irrep_table.xlsx in the working directory, without a message and overwriting an existing file; with --atomic-orbital and no --kpoint it prints one table per special k point and the file keeps the last one. The export goes through pandas and needs openpyxl (or XlsxWriter), which is not a dependency of CrystOD: without either the run stops after the table header with ModuleNotFoundError: No module named 'openpyxl' (pip install openpyxl).

Spin configurations (--axial)#

Which magnetic orderings can the sites of one element take at each k point, sorted by symmetry? --axial takes the place of --orbital: every site of the element carries one axial vector (Rx, Ry, Rz), a magnetic moment, and the output lists the irreps of the spin configurations of those sites (the magnetic representation).

See also

How to read the output.

  • * Basis *: Rx, Ry, Rz, the three components of the moment on every site; the irreps are those of the spin configurations. On an inversion centre they are those of --orbital p with the parity flipped (inversion keeps a spin).

  • GM4+ is the ferromagnet, R4+ the G-type antiferromagnet with the moments in any direction; at X the moments along the wave vector (X3+) separate from the two directions perpendicular to it (X5+).

  • The labels depend on the frame: the bundled example/test_POSCARs/221_PPOSCAR_SrTiO3 has Sr on the origin and Ti on 1b, and gives the labels of that frame: GM4+, R5-, X1- + X5-, M2+ + M5+.

  • The labels are the ordinary ISO-IR irreps of the little group, without the m prefix ISOTROPY gives the time-odd irreps (GM4+ here is mGM4+ there), as in crystod-mag.

  • At a time-reversal-invariant k point a complex irrep and its conjugate are printed once under the pair label with the real dimension, 2.0 [GM3+GM4+(2)] for the Ti sites of P4/m Ti2Ga3, where --orbital lists GM3+(1) and GM4+(1) separately. These are exactly the terms of the survey of crystod-mag -c POSCAR --element EL.

Options and limits

Options and limits.

  • --kpoint (a label or coordinates) and --show-irrep-table work as for --orbital; with --kpoint the header reads * Element (number of atoms) * and * Basis *.

  • --axial does not take --spinor, since a magnetic moment is single-valued, and it is refused with --atomic-orbital, --visualize, --diagram and the other modes.

  • In Python the same decomposition is CrystalOrbital(cell).irreducible_decomposition(k, "Ti", "axial"), which returns the unmerged irreps.

Double-valued irreps (--spinor)#

Which irreps do the orbitals span once spin-orbit coupling is on? With --spinor every orbital carries spin 1/2 and the little groups are the double groups: the crystal orbitals are decomposed into the double-valued (spinor) irreps, those of a calculation with spin-orbit coupling. --atomic-orbital takes the flag as well.

See also

How to read the output.

  • A name -K<n><p> is the double-group label with its overbar written as a leading - (R̄6+ is -R6+, as in the Bilbao tables), the ISO-IR k label, an index n that continues after the single-valued irreps of the k point, and the parity suffix +/- where the single-valued irreps carry one; parity partners share n. At Γ of Pm-3m the single-valued irreps are GM1± to GM5±, so the double-valued ones are -GM6 to -GM8.

  • The numbering is that of Bradley & Cracknell (1972), Table 6.5 (Koster’s Γ numbers), apart from two exceptions (32, 3m, -3m and 4, -4, 4/m). One rule serves --spinor, --atomic-orbital --spinor, --extract-irrep and the WAVECAR-overlap engine (crystod.wavecar_irreps.double_valued_names in Python), so the four name the irreps of one cell alike. An irrep has one name on the whole star of k and at every k + G.

More on reading the output

  • A NOTE: line under the irreps of a k point says where the names differ from Bradley & Cracknell (with and without --kpoint, and with --atomic-orbital):

crystod -c example/test_POSCARs/166_PPOSCAR_Bi --element Bi --orbital p --spinor --kpoint 0 0 0

* Atomic Band Irreducible Representations *
 1.0 [-GM4+(1)] + 1.0 [-GM4-(1)] + 1.0 [-GM5+(1)] + 1.0 [-GM5-(1)] + 2.0 [-GM6+(2)] + 2.0 [-GM6-(2)]
 NOTE: Bradley & Cracknell (1972) number the two-dimensional irrep GM4+- and the pair GM5+-, GM6+- (Table 6.5); here the pair is -GM4+-, -GM5+- and the two-dimensional irrep -GM6+-

  • This line appears where the proper parts of the little co-group form the point group 32 (32, 3m and -3m: Γ and T of R-3m, L of Fm-3m and Fd-3m) and the irreps are, per parity, two one-dimensional and one two-dimensional. Where they form a cyclic group of order 3, 4 or 6 and the irreps at k hold a complex-conjugate pair (Γ of P3 or P4, for example), the line is NOTE: the complex-conjugate pairs are ordered after the single-valued ISO-IR labels; Bradley & Cracknell (1972) Tables 6.5 and 6.14 number them inconsistently.

  • The three-line remark under * Atomic Orbital * (survey) or * Spinor * (--kpoint, --atomic-orbital) states the convention once per run (its text changed in v0.4.7: it used to call the names CrystOD’s own convention and now gives the Bradley & Cracknell numbering and its exceptions).

  • A double-valued irrep that cannot be named keeps the generic key irrep_i(dim), and a NOTE: line under the irreps gives the reason; on the special points of the structures in example/test_POSCARs every irrep is named.

Limits

Limits.

  • The names are not the Bilbao Crystallographic Server (BCS) numbering: at Γ of Pm-3m, CrystOD’s -GM6+, -GM6-, -GM8+ and -GM8- are BCS’s -GM6, -GM8, -GM10 and -GM11. The overlap engine can put IrRep’s Bilbao names on its levels (--vasp-irrep-json).

  • Where the numbering differs from Table 6.5, and anywhere away from Γ, compare a name with another table through the characters (--show-irrep-table) or the fingerprint, not through the number.

  • The two irreps of a tied complex-conjugate pair (little co-groups 2, m, 2/m, 32, 3m and -3m) can swap between frames related by an element of the Euclidean normalizer (an origin shift, an equivalent basis such as (-a,-b,c), a 60-degree rotation in the trigonal groups); compare names between inputs given in the same setting.

How to read the output.

  • The removed sublattice stays in the basis as ghost atoms and acts on the fragment as its formal-charge point lattice (--oxidation Sc=+3 F=-1 overrides the guessed oxidation states): each fragment column is the electronic state before chemical bond formation.

  • The three columns are put on one scale by deep-level (XPS-style) alignment against the deepest chemically inert fragment level (printed with anchor, purity and k-spread); --no-align keeps the raw references instead.

  • Crystal-orbital lines are colored by bonding character (blue = bonding, black = nonbonding, red = antibonding), and the fragment columns are drawn in the VESTA color of each level’s dominant element.

  • Degeneracies are exact by construction: all displayed levels are re-diagonalized from the group-averaged Fock, whose invariance under the AO representation is verified against PySCF’s own overlap matrix (D+ S D = S, residual printed per k point).

The SCF cache

The SCF cache.

  • Because a three-SCF --pyscf run is expensive, the converged densities are cached automatically as CHK_{formula}.chk (rutile TiO2: CHK_TiO2.chk, the reduced formula in conventional chemical order).

  • The next run on the same structure with the same options reads it and skips all three SCFs; a run whose options differ says so and recomputes, overwriting the file; --no-chk neither reads nor writes it.

  • --chk FILE keeps the strict behaviour instead: that file is yours, so a parameter mismatch aborts with crystod --chk-info guidance rather than overwriting it.

Basis sets, pseudopotentials and functionals

Basis sets, pseudopotentials and functionals.

  • Of the GTH basis sets PySCF ships, only gth-szv-molopt-sr and gth-dzvp-molopt-sr cover the transition metals and beyond (H–Rn, with the lanthanides La–Lu absent from every GTH set, so --pyscf cannot run on a rare-earth compound at all — the extended-Hückel engine can).

  • The larger sets (gth-tzvp, gth-qzv2p, the gth-aug-* and gth-cc-* families, …) stop at Ar or cover a handful of light elements, so they buy diffuse and polarization freedom only for main-group compounds.

  • A basis or pseudopotential without an entry for one of the elements is refused with the list of sets that do cover the structure.

  • For --pseudo, gth-pbe, gth-pade (LDA), gth-lda and gth-hfrev span H–Rn, gth-blyp reaches Bi, and the rest are light-element only.

  • --xc accepts most libxc names (a name libxc does not know, and a VV10 functional such as wb97m-v — PySCF’s periodic code has no nonlocal correlation — are both refused up front with the reason); LDA (lda, svwn), GGA (pbe, pbesol, revpbe, blyp, bp86, pw91, b97-d), meta-GGA (scan, r2scan, tpss, revtpss) and hybrids (b3lyp, pbe0, hse06, m06, wb97x, …) all run here, plus hf for Hartree–Fock; hybrids evaluate exact exchange on the FFT grid, so give them --ke-cutoff 150 or more.

How to read the output.

  • * VASP run * gives the run (NBANDS, NKPTS, ISPIN, spin-orbit, ENCUT from the WAVECAR header), the Fermi level (from OUTCAR, else vasprun.xml, DOSCAR or the WAVECAR header; the source is named) and the valence-band maximum: the highest eigenvalue with an occupation above 1/2 over every k point and spin channel of the file, as --vasp-zero vbm takes it.

  • * Special k points in the WAVECAR * lists the analysed k points: the label, the fractional coordinates as stored in the file, the 1-based index in the file (k#), and the little group as the space-group type of its operations (the SALC mode’s “little group of k”).

  • One table per k point: the level number (1-based, in energy order over all bands of the file), the band indices (1-based), the energy relative to the zero (4 decimals), the degeneracy, the irrep — at Γ followed by its Mulliken symbol in parentheses — and a note.

  • * Band edges * gives, per k point, the highest occupied and the lowest empty level with their irreps and the direct gap, and the gap over the whole file (metallic instead when bands are partially occupied).

Options

Options.

  • k points. By default every special point of the space group — the ISO-IR points crystod-bz --show-kpoint lists, the same list --diagram draws — that the WAVECAR holds is analysed, found on any arm of its star and modulo reciprocal-lattice vectors in the run’s own reciprocal basis (the fixture stores X as (1/2, 0, 0)). A special point that occurs several times (a band path passes Γ twice; a full mesh holds every arm) is analysed at its first occurrence and the other indices are listed (also k#149). Special points that are absent are named under the block.

  • --kpoint restricts the analysis to special-point labels (GM, X, …; G/Gamma mean GM) and/or fractional coordinates (0 1/2 0, or 0,1/2,0), in the order given; a coordinate off the special points (on a line or plane) is named by the ISO-IR k label of its little group (LD, DT, …).

  • --all-kpoints labels every k point of the file — symmetry lines, planes and general points included (GP, little group P1 (1)); on the 288 points of the SrTiO₃ band-structure run that takes about 40 s (mostly the symmetry set-up of each little group).

  • --zero vbm (default), efermi or raw (the run’s own eigenvalues); --window EMIN EMAX lists only the levels in that range, relative to the zero, keeping their level numbers (the band edges are taken from all levels).

  • --degeneracy-tol EV (default 1 meV, the overlap engine’s): bands within this window of the first band of a level are one level.

  • Spin. An ISPIN = 2 run gives one table per spin channel (* Band irreps at GM [0, 0, 0], spin up *, then spin down, at every k point); --spin up|down keeps one channel. Each channel is labelled by the irreps of the space group of the POSCAR, which is exact for a ferromagnet; in an antiferromagnet whose spin sublattices are one species in the POSCAR the levels that the magnetic order splits come out unassigned.

  • Spin-orbit coupling. A spin-orbit (vasp_ncl, LSORBIT) run is recognised from the WAVECAR (each band record holds two spinor components): one band holds one electron and the levels carry the double-valued irreps (-GM8+, -R6+; the CsPbI₃ valence-band maximum is -R6+, its conduction-band minimum -R6-), named as by crystod --spinor and the overlap engine (Double-valued irreps). They have no Mulliken symbols; IrRep’s Bilbao names (--vasp-irrep-json of the overlap engine) are not offered here.

The YAML file

The YAML file. -o FILE writes the same content as YAML, in the layout of phonon_irreps.yaml: the metadata (crystod_version, run with the directory, WAVECAR, structure, NBANDS, NKPTS, ISPIN, spin_orbit, ENCUT, E_fermi and its source, VBM and CBM, then space_group, energy_zero, zero_energy, degeneracy_tol, window), the analysed kpoints (k_label, k_position, k_index, little_group, copies), then irreps: one entry per k point (and spin) with its list of levels — level, bands (1-based), energy (eV relative to the zero), degeneracy, irrep (null when unassigned), mulliken (Γ), occupation and note — and finally band_edges and gap. yaml.safe_load reads it; without -o nothing is written. What the run needs, and the limits

What the run needs, and the limits.

  • LWAVE = .TRUE. (a WAVECAR of vasp_std or vasp_ncl; a gamma-only vasp_gam WAVECAR, whose coefficient list is halved, is refused) and the POSCAR the run was done with — -c FILE names another file, but it must be the same cell and origin (the coefficients refer to them; a file in another setting is refused); CONTCAR is not read. The labels refer to that cell: the X, M and R labels depend on the choice of origin (see example/03_hybridization/vasp_SrTiO3/README).

  • A primitive cell (a supercell WAVECAR folds several k points of the primitive zone onto one and is refused).

  • The sublattice runs of crystod --diagram --vasp-setup (BAND_sublattice1, BAND_sublattice2) are labelled as well: each Va point-charge species of the POSCAR (Va2-, Va4+) is a species of its own, as in the overlap engine (the formula reads SrTi(Va2-)3); the labels are those the overlap engine gives the sublattice columns.

  • Time reversal is assumed when a level is classified: a magnetic spin-orbit run (vasp_ncl with an ordered moment) breaks it, and its split pairs then carry the time-reversal partner ... not in this level note.

  • The k points to label must be in the run’s k list: a band-structure run (line mode or the zero-weight special points crystod --diagram --vasp-setup writes) or a Γ-centred mesh that contains them.

  • Errors stop with one ERROR: line: no WAVECAR at PATH, no POSCAR, no special point in the k list (use --all-kpoints or --kpoint), a requested k point that the file lacks (the available special points are listed), an empty, truncated or unreadable WAVECAR, or an unknown precision tag.

Electronic band unfolding of two VASP runs (--unfold)#

Example directory: example/09_band_unfold (testsuite section 9); not distributed: neither the pip package nor the repository holds its two runs (4.1 MB of WAVECARs), so the commands below run on your own parent and child band runs

Which band of the high-symmetry parent does each band of a distorted phase come from? The bands of a low-symmetry child computed in its larger cell come out folded into its smaller Brillouin zone (I4/mcm SrTiO3, two cubic cells, has twice the bands of cubic SrTiO3 at every k). --unfold reads the two finished band runs, the parent in its small cell and the child, and draws the child’s bands in the Brillouin zone of the parent, every level with its share on each parent wave vector it unfolds onto (the scheme of Popescu and Zunger and of fold2Bloch). No new VASP run is needed: the two runs are the ordinary band calculations of the two phases, each along its own path. It is the electronic counterpart of crystod-phonon --unfold, which unfolds phonon bands from force constants.

See also

The weights. Each child level gets a weight W on every parent image k = M^-1 K + g_i (A_child = M A_parent, N = det M images): the share of its plane-wave coefficients that falls on that parent wave vector. The weights of a level add up to its degeneracy and do not depend on how VASP mixes the bands of a degenerate level; another of the equivalent settings of the child in the parent (--trans-mat) puts another arm of a parent star on an image, with the same weights. The markers of the figure have area W and color W/deg; the tables print the share W/deg.

What is read

What is read:

  • the child (--child-wavecar, required): its WAVECAR, or the run directory that holds it, and next to it the POSCAR (--child-poscar FILE names another file of the same cell; CONTCAR is not read), the KPOINTS (the k weights and the labels of the band path), the OUTCAR for E_fermi (else vasprun.xml, DOSCAR or the WAVECAR header) and, when the KPOINTS gives no path, EIGENVAL or vasprun.xml for the k weights;

Of the child WAVECAR, the plane-wave coefficients are read only at the k points that are unfolded, one k point at a time.

Energy zero and range

  • The energy zero is taken from the child run and applied to both runs (--zero vbm, the default: the child’s valence-band maximum over all its k points), so the offsets between the two runs are the raw ones. --zero efermi (or fermi) takes the child’s E_fermi, --zero raw (or none) the eigenvalues as written, and --zero EV any energy in eV; --zero efermi on an insulator is arbitrary within the gap (a NOTE says so). --separate-zero zeros each run at its own reference instead (with --zero vbm or --zero efermi): the setup block prints both values, and the footers of the figure say which zero is in force.

  • Without --window, the energy range follows the spectrum: the figure shows the valence block at or below the zero and the complete range above it (-6 .. 10 eV here), the tables a narrower range (-5.5 .. 6 eV here). Both pages use the same range, --window EMIN EMAX (eV relative to the zero) sets both, and the summary names the range that holds the whole spectrum (--window -35 12). The .dat and .yaml files hold every level whatever the range.

  • Above the completeness limit (here 8.554 eV) some child k miss bands that would unfold there, so the unfolded spectrum is incomplete. The figure shades that region, and the summary says where it starts.

Requirements and limits

  • Two finished VASP runs with LWAVE = .TRUE.: the WAVECAR of vasp_std or vasp_ncl (a gamma-only vasp_gam WAVECAR is refused) and the POSCAR the run was done with. The weights refer to the child’s own cell, which need not be primitive (a NOTE says so); a non-primitive parent cell is unfolded onto as given (the zone the parent run computed), with a NOTE.

  • Any setting, with det M of any size, that crystod-group --supergroup-cif finds for the two POSCARs: the child must be a distorted supercell of the parent, with the same composition per parent cell and no displacement above 1.8 Å.

  • The weights need only the child WAVECAR (and the parent structure); the parent run adds the overlay, the parent columns of the tables, page 2 and the alignment. For a meaningful overlay the two runs should use the same ENCUT, POTCARs and functional (the alignment line shows how well they agree).

  • Spin: an ISPIN = 2 child gets tables and pages per spin channel (--spin up|down keeps one). Its POSCAR symmetry need not be a symmetry of the spin density, so only K and -K relate child k points (for the parent-path view, the overlay and the symmetry checks), and a NOTE says so. An ISPIN = 2 child with an ISPIN = 1 parent is accepted (the parent levels are drawn on both channels, with a NOTE); an ISPIN = 1 child with an ISPIN = 2 parent is refused, and so is a spin-orbit run paired with a scalar one.

  • A spin-orbit (vasp_ncl) child uses the child point group and time reversal, which assumes a non-magnetic, time-reversal-symmetric run (a NOTE says so). For a magnetic vasp_ncl run, read only page 1, the child path view, whose markers use no symmetry of the child.

  • A metallic run is read the same way (the weights do not depend on the occupations); the VBM zero is then the highest level occupied above 1/2, and --zero efermi is usually the better zero.

  • The PAW one-centre part is neglected, and the weights are those of the pseudo wave function (the standard approximation of plane-wave unfolding).

  • The unfolded spectrum is exact at the k points the child run samples; page 2 shows the parent legs the child path misses only at their sampled points (use --unfold-kpoints), and above the completeness limit it is incomplete.

Errors

User errors stop with one ERROR: line and exit status 1:

  • no WAVECAR at the path, or no POSCAR in a run directory (CONTCAR is not used);

  • a POSCAR whose cell is not the cell of its WAVECAR (lattice vectors differing by more than 1e-4 Å);

  • an empty, truncated or gamma-only WAVECAR;

  • two structures that cannot be related by a group-subgroup setting, or a --trans-mat that is not one of the equivalent settings (the valid ones are listed);

  • --zero vbm without an occupied band;

  • an ISPIN = 1 child with an ISPIN = 2 parent, a spin-orbit run paired with a scalar one, or --spin on a run that is not spin-polarized;

  • an output directory that does not exist.

Wrong option syntax is a usage error with exit status 2: an option of another mode, --unfold together with --unfold-kpoints, a missing --child-wavecar, a --trans-mat that is not nine integers, --separate-zero with a numeric --zero, or --zero nan.

In Python the command is crystod.salc.unfold_bands, with crystod.salc.unfold_kpoints for --unfold-kpoints (Python API).

How to read the output.

  • * Site-resolved alignment *: the crystal column is the reference (shift 0), and every fragment level is raised onto it by one shift per (column, element), delta. Each element’s shift is fitted to its symmetry-forbidden probes wherever it has any (fragment levels with no partner irrep in the other sublattice at that k), the line says how many anchors it has, and shell spread ... -> NOT one scale (> 1 eV) flags an element whose shells disagree. The pure counterparts are listed with their measured bonding shift. The report also lists the per-shell means, the site-potential difference between the elements of one column and an occupied-band trace diagnostic that uses no projection.

  • * Measured alignment residual *: the centre-of-gravity residual over every complete (k, irrep) manifold, the noise level of the bond colours.

  • Per k point, the site-symmetry induced representations (the SALC decomposition of every element and shell, against which the irreps read from the PROCAR are checked) and the crystal levels with their compositions. A level whose best irrep weight falls below 0.9 is listed in a purity warning; levels whose projected weight per degenerate partner falls below --vasp-projection-floor (0.30) are dropped, and the report prints the weights bracketing the cut.

  • Bond colours: a crystal level carrying 95 % or more of its projected weight on one sublattice is nonbonding; otherwise it is bonding below, and antibonding above, the composition-weighted energy of its fragment parents (0.3 eV deadband). A level with a parent on an element whose own anchors disagree by more than 1 eV keeps the neutral grey stroke, and so does one whose drawn parents hold less than half of it or whose character would change if the levels the window hides were drawn.

The forms of --vasp

The forms of --vasp. It takes no path (the current directory is the ROOT), one ROOT with the three directories of the table above, or the three run directories in any order — whatever they are named and wherever they live:

crystod --diagram --co-left SrTi --co-right O3 --vasp .
crystod --diagram --co-left SrTi --co-right O3 \
        --vasp ./BAND ./BAND_sublattice1 ./BAND_sublattice2

With three paths the crystal run is the one whose POSCAR carries no Va species, and the order they are given in makes no difference to the output. Two paths, or more than three, are refused in one line that shows the accepted forms. DIR/band is used when it carries the PROCAR. Which sublattice directory is the left and which the right column is decided from the real (non-Va) elements of its POSCAR, never from the number in its name; --vasp-crystal DIR --vasp-left DIR --vasp-right DIR override any one column in any of the three forms.

-c is optional, and it fixes the setting

-c is optional, and it fixes the setting. Without it the structure is the crystal run’s own POSCAR. With it, the analysis is done in the primitive cell of that file — so the irreps agree level for level with the other engines and with crystod -c FILE --element … --orbital … on the same file — and each run is mapped onto that setting: one global origin shift, a permutation of the atoms and lattice-vector wraps, with Va atoms mapping onto the removed ones. The run’s lattice matrix has to be the -c primitive one within a relative 1e-3. A -c file with Sr at the origin and runs written with Ti there is therefore the same analysis, not an error:

crystod --diagram -c POSCAR-finish --co-left SrTi --co-right O3 --vasp .
#  * Setting *
#   ./BAND/POSCAR = the -c cell shifted by (1/2, 1/2, 1/2);
#   atom order Sr Ti O O O -> Sr#1 Ti#2 O#5 O#3 O#4
#   irrep labels refer to the POSCAR-finish setting

The mapping is stated in the terminal report, in the level table, in the JSON ("setting") and as a chip on the page whenever it is not the identity: irrep labels at R, X and M depend on the choice of origin, so it matters which file they belong to. The energies, the projected weights, the site shifts and the connector weights do not — they are the same numbers in either setting. If the -c file and the crystal run are the same crystal in genuinely different bases, the analysis falls back to the crystal run’s own setting and says so; if they are not the same crystal, the run stops with one line naming what differs and suggesting -c BAND/POSCAR.

--vasp-setup writes in the crystal run’s setting

--vasp-setup writes in the crystal run’s setting. -c is optional there too: without it the structure is ROOT/BAND/POSCAR. With it, the -c file names the fragments and fixes the formal charges, but the POSCARs that are written always follow the crystal run’s own cell, origin and ion order — they are ROOT/BAND/POSCAR with one sublattice renamed to Va<q><sign>, line for line. The assignment travels there through the same mapping --vasp uses, and the setting is printed ( setting       : …). Otherwise the two fragment runs would sit on another origin — and, through the -c file’s own lattice constant, on a slightly different cell — than the crystal run they are compared with. A -c file that is not the crystal run’s cell in another setting stops --vasp-setup in one line suggesting -c BAND/POSCAR.

A run directory that already holds a finished calculation (OUTCAR, PROCAR or vasprun.xml) is not rewritten: --vasp-setup stops in one line naming the directory and the files, because the INCAR it would write is not the INCAR that was run. --force overwrites anyway.

Names of the output files

Names. With an ordinary -c file the page is CrystOD_{cell}_vasp.html, as in the other engines. Without -c, or when the -c file lives inside one of the run directories, the name comes from the composition and the space group — CrystOD_SrTiO3_Pm-3m_vasp.html, titled SrTiO3, Pm-3m — so that it is never the run directory’s BAND.

The point-charge sublattices and the modified VASP

The point-charge sublattices. A sublattice run names its switched-off atoms Va<q><sign> (Va2-, Va4+) — a species of a modified VASP that represents them as a smeared Coulomb charge plus a short repulsive wall. The formal charges come from CrystOD’s own oxidation-state resolution (--oxidation). --vasp-setup writes the calibrated wall, VACSIGMA 0.5, VACRWALL 0.45 and VACWALL = 2.5 q e²√(2/π)/σ (--vasp-sigma, --vasp-rwall, --vasp-wall-factor change them; one height is written per Va species). VASP itself is proprietary and is not distributed with CrystOD; the patch that adds the Va species is available to VASP licensees on request. --vasp itself needs no patched VASP — it only reads the output files.

Limits

Limits.

  • Non-spin-polarized runs only: a spin-polarized run is refused with one ERROR: line, and so is a spin-orbit run, which the overlap engine below reads.

WAVECAR-overlap engine (--diagram --vasp --vasp-engine overlap)#

How do the levels of the two sublattices bond in the crystal when no level of a site is protected by symmetry? --vasp-engine overlap needs no energy alignment at all: it uses only the wavefunctions of the two sublattice runs and the eigenvalues of the crystal, so every column is on the crystal’s own scale (E − E_VBM). Use it where the anchor engine’s fit has no symmetry-forbidden level to fit a site to — the B-site s and p shells of SrGeO₃ (Ge 4s/4p) and CsPbI₃ (Pb 6s/6p) at Γ, X, M and R.

Spin-orbit coupling

Spin-orbit coupling. For vasp_ncl runs one band holds one electron, a Kramers pair is one level (drawn with one bar per pair), and the levels carry double-valued irreps: -K<n><p>, named as by crystod --spinor (Double-valued irreps), drawn with an overbar (the CsPbI₃ VBM is R̄6+, the CBM R̄6−). --vasp-irrep-json PATTERN puts IrRep’s Bilbao names (-R6, -R8) on the levels instead, by band index — a path with {run} for the run directory’s name, or a directory holding <run>/irrep-output.json; IrRep is run separately (irrep -code=vasp -spinor -fWAV=RUN/WAVECAR -fPOS=RUN/POSCAR -kpoints=… -kpnames=GM,X,M,R -refUC=1,0,0,0,1,0,0,0,1 -shiftUC=0,0,0 -json_file=irrep-output, without -Ecut, whose truncated basis mislabels high bands). --vasp-scalar-reference JSON names the results of the scalar runs of the same crystal: every spin-orbit level and parent then lists the compatible scalar levels (Γ × D(1/2)) — the CsPbI₃ CBM R̄6− at +0.61 eV comes from the scalar R4− at +1.77 eV.

Limits

Limits.

  • The active space is a minimal valence set: diffuse higher shells (Pb 6d and 7s, Cs 6p, Ge 4d, Sr 5p) are left out by the default rule — change it with --vasp-shells, and test the sensitivity with auto-full.

  • The PAW data of every site come from the crystal POTCAR.

  • The effective outer levels depend on the bands above the frozen window, i.e. on NBANDS.

  • A multiplet cut by the top of the band list stays unlabelled.

Options and outputs

Options and outputs.

  • With --dos, --sigma EV is the width of the Gaussian broadening of the curves (default 0.15 eV; it must be positive, and the TXT summary records it in its header line), not an SCF smearing, and --xrange XMIN XMAX sets the energy range of the plot in eV on the --align scale (default: the whole spectrum); --xrange is refused in every other mode.

  • --band takes no --sigma: its SCF smearing is not on the crystod command line, and neither is that of --dos, so both run their SCFs with integer occupations, apart from the automatic smearing of an odd-electron column and the smeared retry of a column that does not converge (0.2 eV, then 1 eV).

  • Both write a PDF, a CSV of every curve (or every band energy and weight) and a TXT summary, both accept --onsite (neither needs the fragment densities), and both share one checkpoint with the diagram runs.

  • The SCF smearing is one of the parameters a checkpoint records (--chk-info prints a positive value on its method line and adds --sigma to its reuse line), so a checkpoint written by --diagram --pyscf or --visualize --pyscf with a positive --sigma is refused by --band and --dos as written with different parameters.

  • --no-chk is accepted by --band, --dos and --visualize --pyscf as by --diagram --pyscf, but changes nothing there: these modes never use the automatic CHK_{formula}.chk cache and read or write a checkpoint only through --chk FILE.

How to read the output.

  • The block is part of the report of its k point (its content is indented like that of the * k point <k> * block above it); the k coordinates of its title are those of the * k point * blocks (the primitive reciprocal basis of the standardized cell).

  • VBM is the highest crystal level holding electrons and CBM the lowest empty one (the HOMO/LUMO markers of the page; levels within 1 meV count as one edge), named as in the diagram (GM5- #1: irrep and running number), with their energies.

  • allowed (x, y, z) lists the polarizations that can drive the transition (at X of SrTiO3 the pair X1+ / X3- is allowed only for the polarization along k, y here, the pair X1+ / X5- only perpendicular to it, x and z). forbidden means that no polarization can.

  • When the band edge is forbidden, first allowed: gives the allowed occupied -> empty pair of smallest energy difference, with dE.

  • x, y, z are the Cartesian axes of the input POSCAR, the frame of the Raman tensors of crystod-phonon --raman-tensor. An allowed polarization subspace that is not spanned by coordinate axes is printed as vectors in the input frame.

Limits

Limits. The rules are for vertical (direct) one-photon electric-dipole transitions between the levels of the diagram: “allowed” means that symmetry does not forbid the transition, and its strength needs the matrix elements. Which levels form the band edges is the engine’s answer (extended Hückel can get the level order wrong; cross-check with --pyscf or --vasp). Spin-orbit (double-group) levels of --vasp --vasp-engine overlap are not evaluated (the block says so).

From Python

Python API. dipole_selection_rules returns a list of DipoleSelectionRules records (one per special k point), and little_group_dipole_table a LittleGroupDipoleTable; there is no MCP tool for this section:

from crystod import salc
from crystod.vasp_io import read_poscar_cell

cell = read_poscar_cell("221_PPOSCAR_SrTiO3")
diagram = salc.CrystalOrbitalDiagram(cell, ["SrTi"], ["O3"])   # or any engine's diagram
rules = salc.dipole_selection_rules(diagram)       # one record per special k point
[(r.name, r.band_edge.verdict) for r in rules]     # [('GM', 'allowed (x, y, z)'), ...]
salc.dipole_selection_rules(diagram, "X")[0].first_allowed.verdict   # 'allowed (x, z)'
print("\n".join(salc.format_dipole_selection_rules(rules[0], "(0,0,0)")))

levels, _ = diagram.solve_at([0, 0, 0])            # from levels solved elsewhere
edge = salc.band_edge_selection_rules(diagram.builder, "GM", [0, 0, 0], levels["mo"])
table = salc.little_group_dipole_table(diagram.builder, [0, 0, 0])
table.components("GM5+", "GM1+")                   # () = forbidden
table.subspace("GM5+", "GM4-")                     # orthonormal rows of the allowed polarizations

dipole_selection_rules(diagram, kpoint=None) solves each k point with diagram.solve_at unless the engine report has already done so (the rules are cached on the diagram); kpoint takes a special-point name or three primitive reciprocal coordinates. It takes the diagram objects of the EHT, PySCF and VASP PROCAR engines; for the page object of the VASP overlap engine it returns the rules that engine’s report cached. little_group_dipole_table(..., axes="standardized") gives the rules in the axes of the standardized primitive cell instead of the input cell.

Options

Two options control what the sketches show:

  • --diagonalize canonicalizes the degenerate partners (RREF), so the arbitrary unitary mixture the SCF returns becomes axis-aligned — the R5+ t2g triplet of ScF3 turns into pure d_xy / d_yz / d_xz; energies are unchanged.

  • --valence-only drops semicore shells (occupied fragment bands more than 12 eV below the crystal VBM — Sc 3s, Sc 3p, F 2s here; detected automatically and printed) from the drawn wave functions. Their admixture in a valence level is an on-site orthogonality tail whose radial node makes a genuinely bonding σ level look antibonding; levels a semicore shell dominates keep it.

7. Symmetry of the response tensors of a VASP run (--check-symmetry)#

Example directory: example/07_check_symmetry (testsuite section 7); its input, a DFPT run of SrTiO3 I4/mcm (example/39_phonon_unfold/SrTiO3_I4mcm/child/DFPT), is not distributed

Do the response tensors of a VASP run have the symmetry of the crystal, and by how much do they break it? crystod-group --tensor gives the form a property tensor must take in a point group (Neumann’s principle). --check-symmetry goes the other way: it reads the tensors one finished VASP run computed and compares each with its projection onto the form the symmetry of the structure allows.

How to read the output.

  • * VASP run *: the files read, the structure, the run parameters, VASP’s own symmetry settings (ISYM, SYMPREC) and the tensors found.

  • * Space group *: the group, the tensor axes (x ‖ a, z ‖ c of the standard conventional cell, the axes of crystod-group --tensor -c) in the frame of the input file, and every site with its Wyckoff letter, site symmetry and orbit.

  • Per tensor, the independent components with the names of crystod-group --tensor -c POSCAR (eps11, c44, e15; T11, T12 for the site tensors), the raw value, the symmetrized one (the average over the point group, or for Z* and Λ over the site-symmetry group of the atom, the atoms of one orbit made consistent by the space group) and their difference.

  • relative residual is ‖T − T_sym‖ / ‖T‖ of the full Cartesian tensor and max |raw - symmetrized| the largest single component, with its name; for the site tensors the line under it separates the part the site groups remove from the disagreement within the orbits. The relations line is the one of crystod-group --tensor.

  • For Z*, the isotropic part tr(Z*)/3 and the antisymmetric part (A23, A31, A12) of the raw tensors, with whether the site group allows an antisymmetric part (Ti in I4/mcm: A12 = ∓0.334); the acoustic sum rule Σ_κ Z*_κ = 0 and the sum rule Σ_κ Λ_κ = 0 are reported, not imposed.

  • A small residual does not prove a tensor right: with ISYM > 0 VASP symmetrizes Z*, the dielectric tensors, the forces and the stress itself (residuals < 1e-15 above). Quantities VASP does not symmetrize can break the symmetry: above, the ionic-relaxation elastic moduli (C44 against C55, relative residual 2.5e-4) and the shear components of the internal-strain tensors (24 % for the apical O on 4a).

  • The piezoelectric tensor is VASP’s stress type e, the kind piezoelectric-e of crystod-group --tensor, not Nye’s piezoelectric (d). Six-component names use Nye’s L = 1–6 for 11, 22, 33, 23, 13, 12; VASP prints its columns in the order XX YY ZZ XY YZ ZX (L = 1, 2, 3, 6, 4, 5).

Options

Options.

  • FILE is the vasprun.xml or the OUTCAR of the run (either may be gzipped). The vasprun.xml holds only Z* and the dielectric tensors; --outcar OUTCAR adds the rest, and where both files hold a tensor the vasprun.xml (eight decimals against five) is used and the agreement of the two is printed.

  • The structure is the initial structure of the vasprun.xml, or the POSCAR next to the OUTCAR; -c FILE gives another file of the same cell, with the atoms in the order of the run.

  • --tolerance is spglib’s (Å, default 1e-5).

  • --only takes a comma-separated subset of born, dielectric, piezo, elastic, strain.

  • Every run writes vasp_symmetry_<formula>.yaml (-o FILE names it).

The YAML file

The YAML file lists, per tensor, the independent components (raw, symmetrized, tensor axes), the relations, the residuals and the full matrices raw_matrix and symmetrized_matrix in the frame of the input file (3×3, or 3×6 and 6×6 in Voigt order xx yy zz yz zx xy, no factors); the site tensors carry one such entry per atom.

From Python

The same from Python, where symmetrize_tensor projects any tensor (a full Cartesian array in the frame of the structure, or one per atom):

from crystod import group

report = group.vasp_symmetry_report("DFPT/vasprun.xml", outcar="DFPT/OUTCAR")
print(group.format_vasp_symmetry(report))
report.tensor("elastic_ionic").values        # (('c11', raw, symmetrized), ...) in GPa
group.symmetrize_tensor(tensor, "elastic", "POSCAR")                # point group
group.symmetrize_tensor(borns, "V2", "POSCAR")                      # one tensor per atom
group.symmetrize_tensor(borns[2], "V2", "POSCAR", site=2)           # one site group

The files are read by crystod.vasp_io.read_vasprun_response and read_outcar_response, which take the last block of every OUTCAR heading (the intermediate tables of a linear-response run are not the results).
