crystod-example#

Copy the worked examples that ship with the package into a working directory.

Every feature of CrystOD has an example directory in the source tree, example/NN_name/: a README with the commands to run and their captured output, and the input files those commands read. All 41 example directories ship inside the package, without their large or unpublished data, so pip install CrystOD is enough to have them, and crystod-example copies them out of the installed package into a directory of your own, where their commands can run and write their outputs.

I want to …

command

see which example directories ship

crystod-example (or crystod-example --list)

copy one into ./example

crystod-example 17

copy several

crystod-example 17 28 (numbers or names: 17_isotropy_subgroup)

copy into another directory

crystod-example 17 -o work

copy every packaged example

crystod-example --all -o DIR

Note

crystod-example copies whole example directories, each with its README. The --example NAME option of crystod, crystod-phonon, crystod-mol, crystod-bz, crystod-xrd and crystod-search is something else: it copies the input files of a single command, if any, into the current directory and runs that command (see Quick start).

The number in front of a directory name is the section number of the feature, the same in this manual, in example/ of the source tree and in testsuite.py (17_isotropy_subgroup is section 17 of crystod-group). Sizes are those of the packaged files. The missing numbers are the command-line regression sections (7, 24, 27, 38, 41, 44), which have no example directory; section 35, the --subgroup section of crystod-phonon, whose examples are in 33_modulation (the section also holds the crystod-phonon regression tests); section 49 (crystod --extract-irrep), whose inputs are part of 03_hybridization; and section 50, this command. The same list, as plain text, is the file README in the crystod/examples/ directory of the installed package.

Copying an example#

Give one or more numbers or names; the directories are copied into ./example (created if needed):

crystod-example 29

* Example directories *
  29_phonon_activity  crystod-phonon --irreps / --vibration (IR / Raman / silent / acoustic activity at Gamma)

* Copied along (the READMEs above use their files) *
  28_phonon_irrep     used by 29_phonon_activity
  30_phonon_fatband   used by 29_phonon_activity

* Shared inputs *
  test_POSCARs        18 files
  test_XYZs           5 files

* Output files *
  Wrote 43 files (459 kB) under example/

Next: cd example/29_phonon_activity and follow its README.

Then change into the directory and run the commands of its README there:

cd example/29_phonon_activity

The README commands write their outputs next to their inputs, which is why the examples are copied out first and never run inside the installed package.

What lands where:

  • NAME is a number (17, also 017) or a directory name (17_isotropy_subgroup, also with the trailing / that shell completion adds). Several can be given at once.

  • -o DIR (--output DIR) copies into DIR instead of ./example (created if needed): the examples go to DIR/NN_name/, the shared inputs to DIR/test_POSCARs/ and DIR/test_XYZs/. The relative layout is that of example/ in the source tree, so every relative path in a README works in the copy as it does there.

  • Shared inputs. The READMEs read common structures as ../test_POSCARs/221_PPOSCAR_SrTiO3 and molecules as ../test_XYZs/XYZ_CH4.xyz, so test_POSCARs/ (18 structures) and test_XYZs/ (5 molecules) are copied with every example. They hold the files the packaged READMEs use, not all the structures of the source tree’s test_POSCARs/.

  • Copied along. Four examples use files of other example directories (../28_phonon_irrep/...), and those directories are copied with them:

    example

    copied along

    what its README uses there

    29_phonon_activity

    28_phonon_irrep, 30_phonon_fatband

    the force sets of SrTiO3, Si, BaTiO3 and ScF3, and the ScF3 BORN file

    40_md_projection

    33_modulation, 39_xdatcar2adp

    the ScF3 phonopy_params.yaml and POSCAR_I4mcm_3, and the NpT trajectory XDATCAR_every10

    45_python_api

    28_phonon_irrep

    the SrTiO3 cell and force sets

    47_xrd_superlattice

    23_symmetry_mode

    the parent and child CIFs of the symmetry-mode examples

  • --all copies every packaged directory, 218 files and 7.36 MB in total; -o DIR names the destination as above.

Copying again, and conflicts#

A file that is already in place with the same content is kept, so a second example copied into the same directory reuses the shared inputs that are there, and copying the same example twice changes nothing:

crystod-example 29

* Example directories *
  29_phonon_activity  crystod-phonon --irreps / --vibration (IR / Raman / silent / acoustic activity at Gamma)

* Copied along (the READMEs above use their files) *
  28_phonon_irrep     used by 29_phonon_activity
  30_phonon_fatband   used by 29_phonon_activity

* Shared inputs *
  test_POSCARs        18 files
  test_XYZs           5 files

* Output files *
  Kept 43 identical files already under example/

Next: cd example/29_phonon_activity and follow its README.

The outputs that a README run has written next to the inputs are not touched, since they are not packaged files. A packaged file that has been edited in the copy is never overwritten: every target is checked before anything is written, and if one differs the command stops with one ERROR line naming it (up to ten files, then “and N more”) and writes nothing, not even a new directory. Here test_POSCARs/221_PPOSCAR_ScF3 was edited after the first copy, and crystod-example 33 would need it:

crystod-example 33

ERROR: example/test_POSCARs/221_PPOSCAR_ScF3 already exists and differs from the packaged example; nothing was copied (move it away or copy into another directory)

Move the edited file away, or copy into a fresh directory with -o. An unknown name also stops with one ERROR line, which lists the names that exist. Both exit with status 1; a wrong combination of options (--all with names, -o without names or --all) is a usage error with status 2.

Some data of the example/ directories is left out of the package; it stays in the CrystOD development tree. The READMEs mark the commands that need it (“not in the pip package”, or “unpublished, not distributed”); everything else in a packaged README runs in the copy. The left-out data falls into two groups.

Not in the pip package: data that is large or used only by the test suite, and third-party and generated output:

  • Large files. The full NpT trajectory of ScF3 (XDATCAR, 41.7 MB): the examples 39 and 40 use XDATCAR_every10, every tenth frame of the equilibrated part of the same run (3.1 MB), whose ADPs agree with those of the full trajectory to 0.2 %. Every FORCE_CONSTANTS file (28 MB together): the READMEs of 28 write one with phonopy before they use --readfc. The phonopy_params.yaml of 33_modulation/Sr3Ti2O7_I4mmm: its README begins with the two phonopy commands that write it.

  • Reference data of the test suite. The expected.json files and the two extra WAVECAR runs SrTiO3_ISPIN2 and SrTiO3_SOC of 03_hybridization/vasp_wavecar (only SrTiO3 and InP_SOC ship), the debug fixtures of 23 (the AMPLIMODES regression cases 23_symmetry_mode/debugN_*/), and the recorded server answers behind the offline test of 48_mp_search (which ships its README only).

  • test_pyscf/, the PySCF band-structure scripts, which the test suite does not run.

  • Third-party output: ISODISTORT, AMPLIMODES and Bilbao output files.

  • Generated output: HTML pages, PDF plots, VESTA files, CSV tables and PySCF checkpoints. Running the README commands writes them again.

Unpublished, not distributed: the data of work not yet published, that is, the WAVECAR-overlap and meta-GGA (LAK) runs of 03_hybridization (vasp_overlap/, vasp_SrTiO3_LAK/) and the CdF2 supercell of 06_visualized_basis (CdF2_Fm-3m/).

In the source tree, the file example/PACKAGED selects the packaged files and names the directories each example uses. script/sync_packaged_examples.py copies the selection, byte for byte, into crystod/examples/ and writes the index files index.json and README there. Testsuite section 50 checks that the packaged files are exactly that selection and identical to their originals in example/, that every file a README names is there when that example is copied alone, and the crystod-example command itself. See Contributing for adding an example.

From Python#

The same operations are functions of crystod.examples:

from crystod.examples import (ExampleConflictError, copy_example_dirs, example_dir_path,
                              get_example_dir, list_example_dirs, resolve_example_dirs)

len(list_example_dirs())           # 41: ExampleDirectory records, by number
ex = get_example_dir(29)           # also "29" or "29_phonon_activity"
ex.name, ex.requires, ex.bytes     # ('29_phonon_activity', ('28_phonon_irrep', '30_phonon_fatband'), 14600)
ex.files                           # ('29_phonon_activity/README',)
example_dir_path("17")             # its directory inside the installed package
[d.name for d in resolve_example_dirs([29, 45])]
# ['29_phonon_activity', '45_python_api', '28_phonon_irrep', '30_phonon_fatband']

paths = copy_example_dirs([29], "work")     # = crystod-example 29 -o work
len(paths), paths[0]               # (43, PosixPath('work/29_phonon_activity/README'))

try:
    copy_example_dirs([17], "work")
except ExampleConflictError as exc:  # a FileExistsError; nothing was written
    print(exc.paths)               # the files in the way

  • list_example_dirs() returns the packaged directories as ExampleDirectory records (name, number, description, requires, files, bytes; files are paths relative to the package directory, 29_phonon_activity/README), sorted by number. It is empty when the package has no index.json, as in a source tree that has not been synchronized.

  • get_example_dir(key) finds one directory by number or name and raises KeyError, with the names that exist, for any other key. example_dir_path(key) is its absolute path inside the package: read the files there, but run the README commands in a copy.

  • resolve_example_dirs(keys) lists the requested directories and, after them, the directories their READMEs use, each once (requires=False leaves the latter out).

  • copy_example_dirs(keys, destination) is crystod-example: it copies the resolved directories and the shared inputs (shared=False leaves those out), keeps identical files, and returns the paths of all the files of the copy. If any file in destination differs from the packaged one, it raises ExampleConflictError (with the paths in exc.paths) before writing anything.

The single input files of the --example options (example_path, copy_example_files, get_example) are part of the same module; see the docstring of crystod.examples.
