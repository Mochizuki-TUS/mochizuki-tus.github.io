crystod-phonon#

Phonon analyses on top of phonopy data (POSCAR + FORCE_SETS, or FORCE_CONSTANTS with --readfc, or phonopy_params.yaml). Nine mode flags: --irreps, --fatband, --lt, --vector, --modulation, --vibration, --subgroup, --unfold, --visualize.

32. Phonon irreps (--irreps)#

Example directory: example/32_phonon_irrep (testsuite section 32); after pip install: crystod-example 32

Note

The example/... paths on this page are those of a clone of the repository, used from its root. After pip install CrystOD, run crystod-example NN (the number of the example directory) in your working directory first: it copies that directory and the shared test_POSCARs/ into ./example/, and the commands then run from there unchanged (see crystod-example).

Which symmetry type (irreducible representation, irrep) does each phonon mode belong to? --irreps labels the phonon modes at the special q points with their irreps, writes them with their frequencies to phonon_irreps.yaml, and draws next to it the phonon dispersion with these labels, phonon_irreps.pdf (below).

See also

Theory: Irrep labels and the frame of a structure — why one mode can carry different names in different settings of the same crystal, and how a k point on a symmetry line is labeled; Phonon irrep labels on the dispersion — how the labels are placed on the bands of the figure.

- q_label: R
  q_position: [0.5, 0.5, 0.5]
- q_label: X
  q_position: [0.0, 0.5, 0.0]
- q_label: M
  q_position: [0.5, 0.5, 0.0]

irreps:
- q_label: GM
  q_position: [0.0, 0.0, 0.0]
  activity_summary: GM4- x4 (3 IR, 1 acoustic), GM5- x1 (silent)
  band_sets:
  - band_indices: [1, 2, 3]
    irrep_label: ['GM4-(3)']
    mulliken: T1u
    frequency:   0.0000003685
    activity: [acoustic]
  - band_indices: [4, 5, 6]
    irrep_label: ['GM4-(3)']
    mulliken: T1u
    frequency:   2.6629186664
    activity: [IR]
  ...

- q_label: R
  q_position: [0.5, 0.5, 0.5]
  band_sets:
  - band_indices: [1, 2, 3]
    irrep_label: ['R5-(3)']
    frequency:  -1.0867090338
  ...

How to read the output:

  • special_points: the special q points surveyed, with their positions in fractions of the primitive reciprocal basis.

  • band_sets: the modes of a q point grouped into degenerate sets. band_indices are 1-based, so a level can be fed straight back into --vector --mode or --modulation --mode; irrep_label is the ISO-IR label with the dimension in parentheses; frequency is in THz, negative for an imaginary mode (R5-(3) at -1.087 THz).

  • At Γ each set also carries the Mulliken symbol of its irrep in a mulliken: line after irrep_label:, and its spectroscopic activity in an activity: line (section 33); activity_summary sums them up.

  • The terminal prints the Γ activity summary, the k path of the figure and the names of the two files.

  • The name R5- refers to the setting of the input file, which has Sr at the origin; with Ti at the origin, or with an origin that is not a standard one, the same mode is R4+ — see Irrep labels and the frame of a structure for the rules every command follows (origin, axes, supercells, the names of -k stars).

The file phonon_irreps.yaml

  • -o FILE writes the YAML file to another path (-o SrTiO3_irreps.yaml, also with --all-irreps below), and the figure next to it with the same name and .pdf (SrTiO3_irreps.pdf); the * Output files * block at the end of the run names the files written.

The file is YAML, and any YAML library reads it (yaml.safe_load); crystod.phonon.read_phonon_irreps returns it as a dictionary and checks it:

key

content

space_group

Hermann-Mauguin symbol

nac

true with --nac

dielectric_electronic, dielectric_static

eps_inf and eps_0, 3x3 (only with --nac)

special_points

list of q_label, q_position (fractions of the primitive reciprocal basis)

k_path, path_midpoints

the seekpath path and the midpoints of its segments, each with q_label, segment, q_position (only in phonon_irreps_all.yaml)

irreps

one entry per q point: q_label, q_position, segment (at a path midpoint), activity_summary (at Γ), band_sets

band_sets

one entry per degenerate set: band_indices (1-based), irrep_label (list; a set holding several irreps lists them all), frequency (THz, negative for an imaginary mode), and at Γ mulliken, activity and, with --nac, mode_effective_charge and dielectric_contribution

 
from crystod import phonon

data = phonon.read_phonon_irreps("phonon_irreps.yaml")
for point in data["irreps"]:
    for band_set in point["band_sets"]:
        print(point["q_label"], band_set["band_indices"],
              band_set["irrep_label"], band_set["frequency"])
Force constants (--readfc)

The example directories carry FORCE_SETS. For --readfc, write FORCE_CONSTANTS from it with phonopy 4 first, as the README of each 32_phonon_irrep directory does:

phonopy-init -d -c 221_PPOSCAR_SrTiO3 --dim 4 4 4
phonopy phonopy_disp.yaml --writefc --fc-calc traditional
crystod-phonon --irreps --dim 4 4 4 -c 221_PPOSCAR_SrTiO3 --readfc

  • With --fc-calc traditional these are the force constants crystod-phonon builds from FORCE_SETS, and phonon_irreps.yaml is the same up to the ~1e-7 THz noise of the acoustic modes at Γ (phonopy’s default fit, symfc, shifts the SrTiO3 frequencies by up to 0.004 THz).

  • Do not leave a FORCE_CONSTANTS next to FORCE_SETS unless you mean to use it: phonopy reads a FORCE_CONSTANTS it finds in the working directory even when crystod-phonon hands it FORCE_SETS (no --readfc), and that file then wins, so the “FORCE_SETS” run silently uses the force constants.

NAC and the BORN file (--nac)#

The non-analytical term correction is applied only with --nac, in every mode that reads force data (--irreps, --fatband, --lt, --vector, --modulation, --subgroup; not --unfold, which refuses --nac): it then reads BORN from the working directory (--modulation also looks next to the cell file; with --yaml, the NAC parameters stored in the yaml come first, as in phonopy), and stops with an error when there is none. Without --nac a BORN file lying in the directory is not read. The header of phonon_irreps.yaml records the choice (nac: true / nac: false), and the terminal says where the charges came from:

NAC: Born effective charges and dielectric tensor read from BORN.

At Γ itself phonopy applies no q direction, so the --irreps labels and frequencies at GM are those of the TO modes either way; NAC changes the frequencies near Γ, e.g. the LO branch of a --vector or --modulation run at a small q.

Symmetry lines as well (--all-irreps)#

The default survey covers the special points. --all-irreps additionally labels the midpoint of every seekpath path segment — the symmetry lines (DT, Z, SM, LD, S, T, …) — and writes phonon_irreps_all.yaml instead, so both surveys can coexist in one directory:

crystod-phonon --irreps --dim 4 4 4 -c 221_PPOSCAR_SrTiO3 --all-irreps
# -> phonon_irreps_all.yaml, phonon_irreps_all.pdf

k_path: GM-X-M-GM-R-X | R-M  # seekpath
path_midpoints:  # midpoints of the k-path segments, ISO-IR k-vector types
- q_label: DT
  segment: GM-X
  q_position: [0.0, 0.25, 0.0]
- q_label: Z
  segment: X-M
  q_position: [0.25, 0.5, 0.0]
  ...

- q_label: DT
  segment: GM-X
  q_position: [0.0, 0.25, 0.0]
  band_sets:
  - band_indices: [1, 2]
    irrep_label: ['DT5(2)']
    frequency:   2.1278014037
  - band_indices: [3]
    irrep_label: ['DT1(1)']
    frequency:   3.7542651577
  ...

How to read the output:

  • The entries of the lines follow those of the special points in the same irreps list and carry the segment key; a midpoint whose labeling fails gets band_sets: [].

  • This is the labeling that tells a branch apart along a line — which of the two DT5 branches is which — and it is slower than the special-points-only default.

  • The same physical k point gets the same label whichever arm of the star or copy k + G is given (the rule is in k points: star arms, k + G, lines and -k).

  • The k_path and segment names are seekpath’s; for an input outside the ISO-IR setting, an endpoint to which the frame of the labels gives another ISO-IR type than spglib’s frame, in which seekpath names its points, is printed with its ISO-IR name (the seekpath P of a shifted I-4 cell, which carries PA labels, as GM-X-PA-N-...).

crystod-phonon --visualize --all-irreps shows the modes at these midpoints in the browser, with the same labels (section 40).

The dispersion with the labels (phonon_irreps.pdf)#

phonon_irreps.yaml lists the irreps point by point; every --irreps run also puts them on the phonon dispersion. It computes the bands along the k path with phonopy, labels every level at the special points of the path, and draws both into one figure, phonon_irreps.pdf, next to the YAML file. No band.yaml and no plotting script of your own are needed; the figure at the top of the README and of the documentation start page is the one this command writes:

cd example/32_phonon_irrep/SrTiO3_Pm-3m
crystod-phonon --irreps -c 221_PPOSCAR_SrTiO3 --dim "4 4 4"
# -> phonon_irreps.yaml, phonon_irreps.pdf

Reading the figure#

  • One dot, one degenerate level. The label is the ISO-IR small irrep of the level with its dimension in parentheses, exactly the irrep_label of phonon_irreps.yaml (GM4-(3), R3-(2)); a one-dimensional irrep is written without its (1) (X3-, R2-). The dimensions at one point add up to the number of bands: 3 + 3 + 3 + 3 + 2 + 1 = 15 at R for the five atoms of SrTiO3.

  • Γ. The GM4-(3) at 0 THz is the acoustic triplet; the three other GM4-(3) (2.66, 4.71 and 15.31 THz) are the IR-active T1u modes and GM5-(3) at 7.35 THz is the silent T2u mode, as the * Gamma-point activity * block says (see 33. Phonon activity for the Raman/IR selection rules and the Mulliken names).

  • Red: the instability. A level below --threshold (default -0.1 THz) is imaginary; phonopy gives it as a negative frequency and it is drawn in red. Here it is R5-(3) at -1.09 THz, the rotation of the TiO6 octahedra that drives the cubic-to-tetragonal transition of SrTiO3 (R5- in the setting of this file, with Sr at the origin; R4+ with Ti at the origin, see the note on frames above). Which structures it can condense into is the subject of 41. Subgroups from imaginary modes: crystod-phonon --subgroup -c 221_PPOSCAR_SrTiO3 --dim 4 4 4 --qpoint R gives I4/mcm for the direction (0,0,a).

  • Close levels. Labels that would overlap are moved apart, each kept as close to its level as the room allows, and joined to its dot by a leader line: at the right-hand M, M2- (12.74 THz), M5-(2) (12.86 THz) and M1+ (13.13 THz). Two labels at one height are two levels: X2+ at 7.842 THz and X1+ at 7.850 THz are separate one-dimensional levels (two dots); one set holding two irreps would read X1+ + X2+ (the acoustic set GM1 + GM5(2) of P4mm BaTiO3 at 0 THz is such a set).

  • Every point once. A point is labeled at its last place on the path that is not a break: Γ at the middle vertex rather than at the left edge, X at its first vertex rather than at X|R, and M at the right edge, with its labels to the left. Where the path jumps (X|R), the two points get their labels on either side; two equivalent points with the same levels share one set (U|K of fcc Si).

  • The lines between the points are not labeled. The branches along the symmetry lines carry irreps of their own (DT1, DT5(2), … on Γ-X); --all-irreps lists them in phonon_irreps_all.yaml (the figure is the same with or without it), and a --band path with a vertex on the line labels them in the figure (below).

The terminal output

It is the --irreps run of the start of this section (same FORCE_SETS, same phonon_irreps.yaml); the * Band path * block of the terminal names the path drawn and the points that carry labels:

* Gamma-point activity *
GM4- [T1u] x4 (3 IR, 1 acoustic)
GM5- [T2u] x1 (silent)

* Band path *
  k path (seekpath): GM-X-M-GM-R-X | R-M  (306 q points)

* Output files *

The run takes about 4.5 s for this example, one second of it for the bands and the figure. The YAML file is the result of the run: when the figure cannot be drawn (seekpath or the labeling failing on an unusual cell), the * Band path * block gives the reason in one NOTE: the dispersion figure was not drawn (...) line, * Output files * lists the YAML file alone, and the run still ends normally.

Options

The figure is a PDF named after the YAML file: phonon_irreps.pdf (SrTiO3_irreps.pdf with -o SrTiO3_irreps.yaml, phonon_irreps_all.pdf with --all-irreps). These options of --irreps shape it:

option

effect

--band "..."

a path of your own, in fractions of the primitive reciprocal basis; commas separate continuous pieces (default: the seekpath path of the primitive cell, as in --fatband and --lt)

--band-labels "..."

names of the --band vertices (default: their ISO-IR k-vector type, so a vertex on a line is named and labeled too)

--npoints N

q points per leg of the path (default 51)

--threshold F

frequency in THz below which a level is red (default -0.1, the threshold of --subgroup)

--nac

bands with the LO-TO splitting (needs BORN); see the note below

--readfc, --tolerance

as for the YAML file: FORCE_CONSTANTS in place of FORCE_SETS; the degeneracy tolerance of the labels

A malformed --band, a --band-labels count that does not fit it, or --npoints below 2 stops the run with one line before the survey.

A path of your own, here with a vertex in the middle of Γ-X, so that the branches of the line DT are labeled as well:

crystod-phonon --irreps -c 221_PPOSCAR_SrTiO3 --dim "4 4 4" \
    --band "0 0 0  1/4 0 0  1/2 0 0, 1/2 1/2 0  1/2 1/2 1/2"
# -> phonon_irreps.yaml, phonon_irreps.pdf   (add -o band.yaml to write band.yaml, band.pdf and keep the seekpath figure)

* Band path *
  k path (--band): GM-DT-X | M-R  (153 q points)
  Labeled points: GM, DT, X, M, R

The vertex (1/4, 0, 0) is named DT by its ISO-IR k-vector type and gets the DT1, DT2, DT5(2) labels; at the jump X|M the X labels go to the left of the break and the M labels to the right.

Note

With --nac the bands show the LO-TO splitting near Γ, but the Γ labels are those of the TO modes (phonopy applies no q direction at Γ itself; see NAC and the BORN file): the LO branches end at Γ without labels, and the * Band path * block says so in a NOTE: line.

Text is set in Arial, or in DejaVu Sans where Arial is not installed; the figure is 16 cm x 12 cm.

33. Phonon activity (IR, Raman, mode charges)#

Example directory: example/33_phonon_activity (testsuite section 33); after pip install: crystod-example 33

The Γ phonons are the ones first-order infrared absorption and Raman scattering see. This section reads the spectroscopic side of a phonon calculation off them, for assigning measured spectra or checking a calculation against them: which modes are IR active, Raman active or silent, the Raman tensor of each line and, with Born effective charges, what each IR mode adds to the static dielectric constant. There is no mode flag of its own; the results are printed by the commands of the table.

See also

Spectroscopic activity#

At Γ every degenerate set gets its spectroscopic activity, IR, Raman, both, silent or acoustic, and the terminal prints the summary in a * Gamma-point activity * block, one irrep per line:

crystod-phonon --irreps --dim 4 4 4 -c 221_PPOSCAR_SrTiO3


* Gamma-point activity *
GM4- [T1u] x4 (3 IR, 1 acoustic)
GM5- [T2u] x1 (silent)

* Band path *
  k path (seekpath): GM-X-M-GM-R-X | R-M  (306 q points)
  Labeled points: X, GM, R, M

* Output files *
  Phonon irreps written to: phonon_irreps.yaml
  Phonon dispersion with irrep labels written to: phonon_irreps.pdf

How to read it:

  • GM4- [T1u] is the ISO-IR label with its Mulliken symbol in brackets; x4 is the number of degenerate sets that carry it, followed by what they are: here one acoustic set and three IR-active optical sets. The activity_summary: line of phonon_irreps.yaml is the same summary without the brackets, and every Γ set of the file has its mulliken: and activity: lines (section 32).

  • IR active: the mode carries an electric dipole. Raman active: its irrep occurs in the representation of the polarizability tensor. silent: neither. acoustic: the three rigid translations, reported as acoustic rather than IR although their irrep is that of the vector representation.

  • “Active” means allowed by symmetry: the intensity of an allowed line can still be too weak to observe.

  • unknown marks a set whose characters are not those of a representation (too small a --tolerance split a degenerate set; raise it), ? a set that could not be labelled.

  • A set can hold more than one irrep (the acoustic set of a polar crystal, or optical irreps within --tolerance of each other); its activity: line then lists every kind that occurs ([IR, silent, acoustic]), and the summary does not depend on the tolerance.

  • The Mulliken symbols are the ones phonopy itself prints. B1/B2 (and B1/B2/B3) follow phonopy’s axis convention, which can differ from other tables, and refer to the axes of the standard setting even for a cell given in another setting (Pbnm instead of Pnma, for instance).

How to read it (one row per degenerate set, then the totals):

  • |Z~| (e/sqrt(amu)): the size of the mode effective charge of the set, the dipole its displacement carries (the root of the sum of its squares over the bands of the set, which does not depend on how the degenerate eigenvectors were chosen).

  • Delta eps (xx, yy, zz): the contribution of the set to the static dielectric tensor (its diagonal); the acoustic bands are left out (-).

  • eps_inf is the electronic tensor of BORN, and eps_0 = eps_inf + sum Delta eps.

  • The acoustic sum rule line: the Born charges of all atoms of the cell add up to zero; the line gives the largest element of that sum, a check of the BORN file.

  • The Lyddane-Sachs-Teller check compares the product over the optical bands of (nu_LO / nu_TO)^2 with eps_0 / eps_inf along the same direction (q -> 0 along [1 0 0], reduced reciprocal coordinates). The two numbers come out of independent calculations, and their agreement checks the charges, the frequencies and the units together.

  • An imaginary optical mode with a dipole (a polar soft mode) has a negative Delta eps; the table then adds the line note: N imaginary optical band(s) (bands ...) contribute with negative sign; eps_0 is not a static dielectric constant of an unstable structure.

* Output files *

  Phonon dispersion with irrep labels written to: phonon_irreps.pdf

How to read it:

  • The tensors are written in the Cartesian axes of the input cell (the axes of the POSCAR lattice vectors), so that they can be compared with a polarization geometry in the laboratory frame of that cell; a cell rotated in space gives the rotated tensors. The Mulliken symbol in brackets refers to the axes of the standard setting, so for a cell in a non-standard setting (Pbnm instead of Pnma) the tensor of B1g need not be xy.

  • Each tensor of an irrep has its own free constant a, with exact entries where possible (-2*a, sqrt(3)/2*a). A complex irrep is listed together with its conjugate (GM2GM3).

  • For an irrep that occurs once in the symmetric square the tensors are its partners (the cubic Eg pair diag(a, a, -2a) and diag(a, -a, 0)). A one-dimensional irrep that occurs twice (A1 of 4mm and 6mm) prints its two basis tensors, and a mode’s tensor is a combination of them (diag(a, a, b)).

  • An irrep of dimension two that occurs twice (E of 3m, -3m and 32, and the complex E pair of 3 and -3) is printed per partner instead (2 partners, constants a, b), with constants shared across the partners, as in the tables; the two partners of a mode of the irrep have these forms with the same a and b:

The Eg tensors of Bi

Limits

Limits:

  • The activities and tensors are symmetry selection rules for first-order (one-phonon) IR absorption and Raman scattering at Γ: they say which lines can appear and in which polarizations, not their intensities (the dielectric table gives the IR oscillator strengths from the Born charges; Raman intensities need the polarizability derivatives).

  • The point group is that of the atomic structure; magnetic order is not taken into account.

  • --raman-tensor takes Γ only (--vibration at another q point stops with an error).

From Python

Python API. The MCP tool is crystod_phonon_activity (the Γ activity table, the Wyckoff-orbit breakdown and the Raman tensors of a POSCAR, without force constants). gamma_mode_activities prints nothing on stdout: the primitive-cell note of the commands is left out, so it cannot reach the protocol stream of the MCP server (see quiet in What is written):

from crystod import phonon
from crystod.vasp_io import read_poscar_cell

cell = read_poscar_cell("221_PPOSCAR_SrTiO3")    # or a phonopy object with forces
phonon.gamma_mode_activities(cell)               # list of Activity records, one per mode space or set
phonon.gamma_raman_tensors(read_poscar_cell("227_PPOSCAR_Si"))   # list of RamanTensors
phonon.mulliken_symbols(cell)                    # {'GM1+': 'A1g', ..., 'GM4-': 'T1u', ...}

import phonopy                                   # example/34_phonon_fatband/ScF3_Pm-3m
ph = phonopy.load(unitcell_filename="221_PPOSCAR_ScF3", supercell_matrix=[4, 4, 4],
                  force_sets_filename="FORCE_SETS", born_filename="BORN", is_nac=True)
phonon.dielectric_response(ph).eps_static        # DielectricResponse; diagonal 7.5919

The VESTA files

Files are auto-named POSCAR_<formula>_<qlabel>_mode<N>_<irrep>.vesta (mode numbers zero-padded so ls lists them in order) and open directly in VESTA, showing the equilibrium structure with red arrows for the real part of the mass-weighted eigenvector displacement, rescaled so that the largest displacement equals --amplitude (default 1.5 Angstrom).

The q point (--qpoint)

--qpoint accepts a high-symmetry label (GM, X, L, …) or three primitive reciprocal coordinates (fractions allowed). For a q point that is not special, the file name carries its ISO-IR k-vector type (SM, DT, …); --keep-q-coords names it by coordinates instead (see section 37), so a scan along one symmetry line does not overwrite itself.

--modulation is the one mode that does not need --dim — --irreps/--fatband/--lt/--vector/--subgroup still do. It resolves the supercell of the force calculation in this order, and always prints what it used, so an inferred supercell is never silent:

Note

The -c route takes the primitive cell the way every other crystod-phonon mode does — primitive_matrix="auto" — while a phonopy_params.yaml carries whatever primitive matrix it was built with. For a primitive input cell (any P lattice) the two coincide, which is why the commands above agree byte for byte; hand -c a centred conventional cell and the -c route works in the smaller primitive cell instead. Case 3 counts atoms, so it fixes only the product n1*n2*n3; the shape is picked to respect the metric of the cell (|a| = |b| forces n1 = n2). A supercell that is not diagonal

A supercell that is not diagonal is refused rather than guessed at — any diagonal guess with the right atom count loads without complaint, so the error would otherwise be silent:

ERROR: 'phonopy_disp.yaml' states a supercell_matrix that is not a positive diagonal matrix; this workflow supports diagonal supercells only. Inferring one instead would silently give the wrong answer, since any guess with the right atom count loads without complaint. Use --yaml phonopy_params.yaml, or give the diagonal supercell with --dim "n n n".

Note

The space group is reported at a 0.1 Å tolerance by default, which is what makes a nearly-symmetric distortion read as the symmetric one. Pass --tolerance 1e-5 to classify the structure at the tolerance the order-parameter direction implies: --mode 1 2 3 --amplitude 0.3 0.15 0.075 is the direction (a,b,c) and prints P-1 at 1e-5, but C2/c at the default, because the smallest of the three displacements is below 0.1 Å. The 1e-5 result is the one to report. --tolerance also sets the tolerance of the mode construction itself (default 1e-5).

What is frozen in#

--modulation freezes in the harmonic eigen-displacement of the chosen modes: phonopy’s eigenvector divided by the square root of the atomic mass, with its Bloch phase, so heavy atoms move less than light ones. For a non-degenerate mode at a time-reversal-invariant q it is, up to its sign, the pattern phonopy’s own MODULATION freezes in (the test suite compares the two, section 37). In practice:

  • --amplitude (Å) is the norm of the displacement of one primitive cell (default 0.3 Å). At a time-reversal-invariant q (2q a reciprocal lattice vector: Γ and the zone-boundary points such as X, M, R, N) every primitive cell of the supercell is displaced by a pattern of norm exactly A; at any other q the real displacement varies from cell to cell along the modulation.

  • q may be written any way. q + G is the same modulation as q: (0.5, 0.5, 0) and (-0.5, 0.5, 0) of Sr3Ti2O7 write the same structure. Two different arms of the star are two different modulations (domains related by a rotation of the parent); the printed star lists them.

  • One --mode number of a degenerate level is one partner, an order-parameter direction of the irrep, and equal amplitudes give the combined directions (--mode 1 2 3 of the R4+ triplet of ScF3 is (a,a,a), R-3c; --mode 1, 2 and 3 alone rotate the octahedra about a, b and c). Which subgroup --mode N gives does not depend on the origin, the orientation or the lattice basis of the input cell; --subgroup --modulate generates every direction.

  • At any other q the global phase is a convention: a structure frozen there is one member of a family related by a shift of the modulation along the lattice, and its space group is the one of that member.

  • The cell is used as it is. The primitive cell of the phonopy object keeps its origin, orientation and lattice basis in the output (the atoms are only grouped by species, as a POSCAR needs). That cell must be primitive (primitive_matrix="auto", which -c uses); a phonopy_params.yaml that stores the conventional cell of a centred lattice as its primitive cell is refused with a message saying so. A structure that is symmetric only within a loose --tolerance is refused as well: symmetrize it before the force calculation.

  • q must be commensurate. A q that no supercell of at most 12 cells per axis holds (0.15, for instance) is refused before any mode is computed, and the message names the smallest supercell that holds it (20x1x1 for 0.15 = 3/20); give q as fractions with a denominator of at most 12 (1/7). The mode table at such a q can still be previewed without --mode. --vibration makes the same check.

The displacement formula and the full conventions (signs, the order of the partners, complex irreps) are in The frozen-in displacement of a phonon mode.

  • The POSCAR lists the atoms grouped by species (Sc F / 8 24), in the order the species first appear.

What is written#

The component is frozen in as u_j(R) = A Re[ w_j exp(2 pi i q.R) ], with A the --amplitude and w a unit-norm symmetry-adapted partner of the selected mode space. There are no force constants and no masses here: w is a displacement pattern that transforms as its irrep, not a normal mode. In practice:

  • At a time-reversal-invariant q (Γ and zone-boundary points such as X, M, R, N, Y) every component is real, the displacement of each primitive cell has the norm A, and a single component freezes into an isotropy subgroup of its irrep (all six X3- spaces of Sr3Ti2O7 give Cmcm; the three R4+ components of ScF3 are the I4/mcm rotations about a, b and c, in that order).

  • Pick the mode space by its label in the listing of the q you use: the mode-space numbers follow the order in which the irreps are listed at the q given, and that order can differ between the spellings q, q + G and -q (SrTiO3 I4/mcm lists M3+ first at 0.5 0.5 -0.5 and M1+ first at 1.5 0.5 -0.5); the k-th mode space carrying a label writes the same file for every spelling.

  • An irrep that occurs several times has one mode space per occurrence. Without force constants nothing selects a combination of them, and any combination freezes into the same subgroup.

  • At any other q the component is a complex Bloch wave whose global phase is a convention, as in --modulation, and the space group of the structure depends on it.

  • The cell is the spglib primitive cell of the input (the Inputed cell was converted into primitive cell note), which is also the cell the supercell is built from; the q coordinates and the Bloch factors refer to it. The commands print that note on stdout; in Python, phonon.SymmetryOnlyVibrations(cell, quiet=True) runs the same analysis without it (for library use, and for the MCP server, whose stdout is its protocol stream).

The full conventions (the partners and their signs, the order of repeated irreps, complex pairs, the labels of shifted inputs) are in Conventions of the symmetry-only vibration patterns.

39. Phonon band unfolding (--unfold)#

Example directory: example/39_phonon_unfold (testsuite section 39); after pip install: crystod-example 39

The phonons of a distorted phase are computed in its own, larger cell and come out folded into its smaller Brillouin zone: Pnma CaTiO3 (20 atoms, four cubic cells) has 60 branches at every k, and which of them carries a cubic mode cannot be read off its band plot. --unfold draws the phonons of the distorted structure (the child) in the Brillouin zone of its high-symmetry parent instead, each child mode with the weight of its projection onto the parent Bloch states (P. B. Allen, T. Berlijn, D. A. Casavant and J. M. Soler, Phys. Rev. B 87, 085322 (2013)), and labels every unfolded level with its parent irrep. The modes that are imaginary in the parent, the octahedral tilts R4+ and M3+ of cubic CaTiO3 and its polar Γ mode GM4- [T1u], reappear in the child at real frequencies, and the run lists the child Γ levels they go into.

What is read

What is read:

  • the child: its POSCAR (--child-poscar, or -c) and the FORCE_SETS of its supercell (--child-dim, or --dim; FORCE_CONSTANTS with --child-readfc), next to the POSCAR, else in the working directory;

  • the parent: its POSCAR (--parent-poscar, always needed), which fixes the transformation, the band path and the irrep labels. Its force data are optional: with --parent-dim its FORCE_SETS (FORCE_CONSTANTS with --parent-readfc) is read next to the parent POSCAR, and the run adds the parent bands, the parent levels at the special points and the child levels the soft parent modes go into.

In each place a force file named after the POSCAR comes first: FORCE_SETS_POSCAR_child next to POSCAR_child (the name macer gives the force data of each structure; FORCE_CONSTANTS_POSCAR_child with --child-readfc), then FORCE_SETS. macer names that file after the POSCAR it was given, the unrelaxed input, while the forces belong to the cell it relaxed (the POSCAR and CONTCAR-<name> it writes): give the relaxed cell as the POSCAR, with the force file named after it or as FORCE_SETS next to it. With these per-structure names, child and parent can share one directory: with POSCAR_child, POSCAR_parent, FORCE_SETS_POSCAR_child and FORCE_SETS_POSCAR_parent in the working directory the command is literally

crystod-phonon --unfold --child-poscar POSCAR_child --child-dim 2 2 2 --parent-poscar POSCAR_parent --parent-dim 2 2 2

The example keeps the two structures in two directories instead (child/ and parent/, each with its FORCE_SETS). When the child and the parent would read the same file the run stops with an ERROR. Every phonopy load runs in an empty temporary directory with absolute paths, so a FORCE_CONSTANTS lying in the working directory is never read in place of FORCE_SETS (the trap described in section 32). The two structures need no common setting, origin or atom order: the transformation and the pairing of the atoms are worked out from the structures themselves.   • transformation: the setting exactly as crystod-group prints it for the same two files (its * Transformation matrix (parent -> child) * block, the AMPLIMODES convention): the columns of P are the child basis vectors in parent units, the last column is the origin shift p, and x_parent = P x_child + p.

  • M (rows): the same setting in the convention of the unfolding and of --trans-mat: the rows of M are the child lattice vectors in parent units, A_child = M A_parent with the lattice vectors as rows, and fractional wave vectors transform as k_child = M k_parent.   • K = M k (child) and child point: where each parent vertex lands in the child zone; distances are in 1/Å without 2 pi, in the reciprocal metric of the pseudo-parent cell.

  • to child GM: yes for an arm that folds onto the child Γ point, where a condensed distortion lives; path: the arm is on the band path.

Weights#

The weight P_J(k) of child mode J at the parent k, between 0 and 1, is the squared norm of its projection onto the Bloch states of the parent translations: how much of the mode is a parent phonon of wave vector k. When reading it:

  • At every k the weights of all child modes add up to 3 n_parent (15 for CaTiO3); the summary block prints the deviation, and above 1e-6 the run stops with an internal ERROR.

  • An undistorted supercell of the parent gives weights of 0 or 1 at exactly the parent frequencies; the further the weights spread over the child modes, the more the distortion mixes the parent branches.

  • Inside a degenerate level (|df| <= 1e-4 THz) only the sum P_g of the level has a physical meaning; where two levels closer than 1e-4 THz form one group, read such groups by their P_g.

  • Page 1 draws one marker per child mode and leaves out the modes with a weight below --weight-min (default 0.02); page 2, the labels and the tables work per degenerate group with its weight P_g, and a group with P_g below --weight-min is not drawn and gets the label -. The .dat file keeps every row.

  • The weights are not those of phonopy’s phonopy.unfolding.core.Unfolding, which keeps the Bloch phase of the actual atomic positions (see CrystOD for phonopy users).

Parent irreps of the unfolded levels#

Every unfolded level is labeled with the parent irreps it belongs to: the ISO-IR labels --irreps gives the parent POSCAR, with the Mulliken symbol at Γ. Like those, they refer to the origin of the parent file: with Ti at the origin the two tilts are R4+ and M3+, with Ca at the origin the same tilts are R5- and M2+ (see Irrep labels and the frame of a structure).

A degenerate group of child modes gets one label for all its members:

  • the irrep holding at least 50 % of the group weight P_g (M3+);

  • else the smallest set of irreps that the child symmetry cannot separate and that holds at least 50 % together, written A/B: at k = (0.49, 0.49, 0) on the Σ line the level at 3.559 THz has 39 % SM1, 39 % SM2 and 22 % SM3 and is labeled SM1/SM2;

  • else mixed, and - below --weight-min.

Limitations

  • No NAC: --nac is refused, because unfolding the LO/TO-split bands near Γ needs the direction of approach to Γ.

  • The parent must be related to the child by a group-subgroup setting that crystod-group --supergroup-cif finds, with the same composition per parent cell and no displacement above 1.8 Å.

  • A child file that is not a primitive cell is unfolded on its primitive cell, as a centered parent is (the setup block says so); an exact supercell of the parent is thereby reduced to the parent cell itself and has N = 1.

  • phonopy symmetrizes the force constants it builds from a FORCE_SETS but takes a FORCE_CONSTANTS as it is, so the two files of one calculation give slightly different weights (the sizes for the two examples are in the theory section); only the sum over a level has a meaning (see Weights).

  • The usual (type-1) FORCE_SETS stores the number of supercell atoms but not the shape of the supercell. A wrong number of atoms stops the run with an ERROR; a wrong --child-dim (or --parent-dim) with the right number, 4 2 1 for a 2x2x2 calculation, is not caught by that check. phonopy then either stops with its own ERROR (“Input forces are not enough to calculate force constants”, as for both example parents and the AlF3 child) or, as for the CaTiO3 child, builds wrong force constants that show up as spurious imaginary frequencies.

  • The labels of a distorted child are a decomposition of the unfolded vectors into parent irreps, not symmetries of the child: within a set the child symmetry cannot separate the mixing is real, and near 50 % the rule can move a level between one irrep and a set.

  • The domain average assumes equal domain populations and averages at equal fractional k of the pseudo-parent cells; for a strongly strained child (AlF3, -9.66 % in volume) these are not exactly the same Cartesian wave vectors in every domain.

  • The origin of the child modes in parent k and irreps is listed at the child Γ point only (not along a path of the child zone); phonons only: the electronic bands of two VASP runs are unfolded by crystod --unfold.

  • Checked so far on centrosymmetric children (Pnma and R-3c) of the symmorphic parent Pm-3m, and on a Pnma cell unfolded onto itself; a polar or chiral child and a non-symmorphic parent with a distorted child have not been tested.

In Python the steps are functions of crystod.phonon: load_unfold_inputs, find_parent_mapping, make_parent_path, unfold, domain_average, irrep_resolve and gamma_origin (Band unfolding onto the parent zone).

The terminal lists, for every q point of the page, the table the page shows (the band, its frequency, the label of its degenerate set and its component inside the set; at GM also the Mulliken symbol and the activity) and the display cell of its pattern. Reading the page#

  • q point: one button per labeled special point of the path, with its coordinates as fractions of the primitive reciprocal basis, in the order in which the path first reaches it (GM, X, M, R). A point the path visits twice (GM) sits at the vertex the --irreps figure labels. With --all-irreps the segment midpoints follow on a row of their own (below).

  • Mode table: Band (1-based, frequency order), Freq (THz) (negative: imaginary), Irrep (the label of the degenerate set as phonon_irreps.yaml writes it: GM4-(3), X3- for a one-dimensional irrep, GM1 + GM5(2) for a set holding several irreps), Comp. (the component inside the set, 1 to its dimension) and, at GM, Mulliken (T1u) and Activity (IR, Raman, IR+Raman, silent, acoustic). The rows of a level below --threshold (default -0.1 THz) are red. Click a row to show the mode; the up and down arrow keys step through the table.

  • Dispersion: click a dot to select its q point and the first component of its level; the selected level is ringed, imaginary branches and dots are red. Hovering a dot shows its label and frequency. With --all-irreps the segment midpoints have their dots too, in the middle of their legs.

  • Arrows: the real part of the displacement pattern at phase 0, from the equilibrium position of every atom; a displacement below 2 % of the largest gets no arrow. The amplitude slider sets the largest displacement in Å (default 0.25 times the nearest-neighbor distance, rounded to 0.05 Å: 0.5 Å for ScF3 and SrTiO3).

  • animate: the atoms move along the pattern as the phase runs through a cycle (the speed slider sets the cycles per second); arrows, bonds and polyhedra move with them. Unchecking returns to the static pattern.

More on reading the output

  • Display cell: the smallest supercell over which the Bloch phase of q is periodic, as --vector builds it: 1 x 1 x 1 primitive cells at GM, 1 x 2 x 1 at X, 2 x 2 x 1 at M, 2 x 2 x 2 at R (--conventional: the conventional cell times the multiples q needs; a segment midpoint: 1 x 4 x 1 at DT (0, 1/4, 0)). Atoms on the cell faces are drawn on both faces, as VESTA does, each with the phase of its own lattice translation. The line under the display controls names the cell, and at a segment midpoint its segment (Segment: GM-X (midpoint)).

  • Bonds and polyhedra (--bond EL1 EL2 MAX, repeatable): the bonds up to MAX Å and the coordination polyhedra around EL1, as in crystod --visualize; the periodic images that complete the polyhedra are drawn too, and move with the pattern.

  • View along a / b / c: an orthographic view down that axis of the display cell (reset returns to the perspective view); drag to rotate, scroll to zoom; the compass in the corner follows the view. The show ... checkboxes hide the arrows, the cell edges and axes, the atoms, the bonds and the polyhedra.

The midpoints and their display cells

The midpoints follow the special points in path order, as in phonon_irreps_all.yaml: for the seekpath path the same points, names and segments; for a --band path the midpoints of its own legs, named by their ISO-IR k-vector type. Each is labeled at the midpoint itself, so its labels are those of phonon_irreps_all.yaml band by band (testsuite section 40 compares them). Its display cell is commensurate with the exact fractions of the midpoint: DT (0, 1/4, 0) gets 1 x 4 x 1 primitive cells (20 atoms), LD (1/4, 1/4, 1/4) 4 x 4 x 4 (320 atoms). A midpoint whose display cell would hold more than 1000 atoms is not drawn; a NOTE in * Band path * and on the page names it and the --qpoint that draws it. On the fcc path of Si these are the two SM midpoints, of X-U and of K-GM:

  NOTE: the midpoint SM (3/16, 3/16, 3/8) of K-GM is not drawn: its display cell would hold 4096 atoms (give --qpoint 3/16 3/16 3/8 to draw it)

while DT (1/4, 0, 1/4) of GM-X, LD of GM-L, Q of L-W and V of W-X are drawn (the largest on 2 x 8 x 8 primitive cells). For the SrTiO3 example the run takes about 4.5 s and the page is about 195 kB.

The midpoints on the page

On the page the midpoints have a row of buttons of their own under “Segment midpoints” (DT (0, 1/4, 0); when two midpoints share a name, two arms of one line type, the button adds the segment: SM (X-U) and SM (K-GM) for Si with --conventional) and a dot on every level in the middle of their leg of the dispersion, which selects them as the dots of the special points do. The hash opens a midpoint by its name (#q=DT, the first point so named), by its name and segment (#q=DT(GM-X)) or by the position of its button (#q=5, the fifth q button).

How the pattern is built#

The partners of a degenerate level are the symmetry-adapted eigenvectors of --vector, and the page draws each one as phonopy’s modulation would: the eigenvector divided by the square root of the atomic mass, with its Bloch phase. In practice:

  • Testsuite section 40 checks that the drawn pattern reproduces phonopy’s modulation on the display cell, atom by atom, to 1e-6.

  • At a time-reversal-invariant q (2q a reciprocal lattice vector: GM, X, M, R of a cubic cell) the patterns of the symmetry-adapted partners are real: every atom moves back and forth along its arrow. At any other q (K of a hexagonal crystal, a point on a line) a pattern is complex in general: the atoms run on ellipses, and the arrows show the phase-0 snapshot.

  • With --nac, the patterns and labels at GM are those of the TO modes (phonopy applies no direction of approach at GM itself; the NOTE of * Band path * says so), while the bands near GM and band_vector.yaml carry the LO-TO splitting.

band_vector.yaml

band_vector.yaml is the band.yaml that phonopy writes for its band structure with eigenvectors (phonopy --eigvecs), along the path of the page (the --irreps path: seekpath, or --band, 51 q points per leg or --npoints), its vertices named by their ISO-IR labels:

      - [ -0.06380814382605, 0.00000000000000 ]
    - # atom 2

Each band carries its eigenvector: one list per atom of the primitive cell with the [re, im] pairs of its x, y and z components, the mass-weighted eigenvector of phonopy’s dynamical matrix in phonopy’s atom-position phase convention (unit norm over the whole vector). These are phonopy’s plain eigenvectors at every q of the path, not the symmetry-adapted partners the page draws (within a degenerate level they can be any orthonormal combination). phonopy’s own tools (phonopy-bandplot) and any YAML reader (yaml.safe_load) read the file. Its name is fixed; -o renames the page only.

Limitations

  • The display cell of a general q is large: each axis is multiplied by the denominator of q (fractions with denominators up to 48), so --qpoint 0.3 0.1 0.2 draws 10 x 10 x 5 primitive cells, 2651 atoms for ScF3. Above 1000 atoms the run prints a NOTE in the block of that q point; the page still works, more slowly. The cell is a diagonal multiple of the primitive (or conventional) cell, not the smallest supercell commensurate with q.

  • With --all-irreps, a segment midpoint whose display cell would hold more than 1000 atoms is skipped with a NOTE (the 16ths of the fcc path: 4096 atoms for Si); --qpoint with its coordinates draws it.

  • The bond search of --bond compares every EL1 atom with every EL2 atom in the 27 periodic images of the display cell (vectorized with NumPy, but its cost grows with the square of the number of atoms): about 1 s for a few hundred atoms.

  • The page loads plotly 2.32.0 from its CDN, as the SALC viewer does, so the first opening needs network access (the browser keeps it afterwards).

  • Arrows are in Å, but the atoms are drawn as markers of a fixed size in pixels: a short displacement can hide inside its atom. Zoom in, raise the amplitude, uncheck show atoms, or look down an axis.

  • During the animation the polyhedra keep the faces of their equilibrium shape, which is right for the small amplitudes a vibration has.

  • The modes are shown at the labeled special points of the path, with --all-irreps also at the midpoint of every segment, or at one --qpoint (any q, by its coordinates); not at every q of the dispersion.

In Python the page is built by crystod.phonon.phonon_viewer_data and written by write_phonon_viewer_html; write_band_vector_yaml writes the YAML file (Phonon mode viewer).

41. Subgroups from imaginary modes (--subgroup)#

Testsuite section 41

When a phonon band goes imaginary, the structure is unstable against the distortion of that mode, and the symmetry it can lower to is fixed by the irrep of the mode. --subgroup labels every imaginary mode and lists the isotropy subgroups of its irrep — the possible daughter phases — in one step.

See also

How to read it:

  • * Imaginary mode at q = ... (R) *: the q point, and the modes, the frequency and the irrep of the imaginary level. The name in parentheses is that of the tabulated star q belongs to, in the frame of the labels; a q point outside the tabulated stars (a point on a line, or the -k partner PA of P in I-4) is printed without a name, its levels carrying their ISO-IR labels (PA3, …).

  • Each row of the table is one order-parameter direction of the degenerate level with the isotropy subgroup it leads to (subgroup, size, index, as in crystod-group --parent). Freezing in a single eigenvector explores only one of them: the R-point triplet of cubic SrTiO3 gives I4/mcm along (0,0,a), but the same triplet also reaches R-3c along (a,a,a) and Imma along (0,a,a).

Options

Options:

  • Without --qpoint, every q point commensurate with the supercell is scanned (64 of them for a 4x4x4 supercell) and the imaginary levels are reported most unstable first, so the unstable q points do not have to be known in advance. With --qpoint R (a label or three coordinates) only that q point is analyzed.

  • --threshold sets the frequency below which a mode counts as imaginary (default -0.1 THz; the acoustic modes at Γ, rigid translations, are never listed, whatever the threshold).

  • --yaml phonopy_params.yaml may be used instead of --dim/-c.

  • The same enumeration is available programmatically as crystod.phonon.imaginary_mode_subgroups.

Generating the daughter structures (--modulate)#

--modulate runs the --modulation step for every listed direction, so the candidate structures of a structure search come out of the same command:

crystod-phonon --subgroup -c 221_PPOSCAR_SrTiO3 --dim "4 4 4" --qpoint R --modulate

* Distorted structures (amplitude 0.3 A) *
R5-(0,0,a)             I4/mcm     -> MPOSCAR_R_R5-_0-0-a_I4mcm
    crystod-phonon --modulation -c 221_PPOSCAR_SrTiO3 --dim "4 4 4" --qpoint 0.5 0.5 0.5 --mode 1 --amplitude 0.3
R5-(0,a,a)             Imma       -> MPOSCAR_R_R5-_0-a-a_Imma
    crystod-phonon --modulation -c 221_PPOSCAR_SrTiO3 --dim "4 4 4" --qpoint 0.5 0.5 0.5 --mode 1 2 --amplitude 0.3 0.3
R5-(0,a,b)             C2/m       -> MPOSCAR_R_R5-_0-a-b_C2m
    crystod-phonon --modulation -c 221_PPOSCAR_SrTiO3 --dim "4 4 4" --qpoint 0.5 0.5 0.5 --mode 1 2 --amplitude 0.3 0.16434
R5-(a,a,a)             R-3c       -> MPOSCAR_R_R5-_a-a-a_R-3c
    crystod-phonon --modulation -c 221_PPOSCAR_SrTiO3 --dim "4 4 4" --qpoint 0.5 0.5 0.5 --mode 1 2 3 --amplitude 0.3 0.3 0.3
R5-(a,a,b)             C2/c       -> MPOSCAR_R_R5-_a-a-b_C2c
    crystod-phonon --modulation -c 221_PPOSCAR_SrTiO3 --dim "4 4 4" --qpoint 0.5 0.5 0.5 --mode 1 2 3 --amplitude 0.3 0.3 0.16434
R5-(a,b,c)             P-1        -> MPOSCAR_R_R5-_a-b-c_P-1
    crystod-phonon --modulation -c 221_PPOSCAR_SrTiO3 --dim "4 4 4" --qpoint 0.5 0.5 0.5 --mode 1 2 3 --amplitude 0.3 0.16434 0.08913

  • One POSCAR per direction, plus the --modulation command that reproduces it — copy-paste it as printed and it rewrites exactly that file, so an amplitude or a mode can be changed afterwards without working out the combination again.

  • The file is named after the space group --modulate measured at 1e-5; the command reports the one at --modulation’s default 0.1 Å, where a direction with a small component can read as a more symmetric neighbour (R5-(a,b,c) above prints C2/c): add --tolerance 1e-5 to the command to see the same group.

  • --amplitude scales all of them (default 0.3 Å). The names read MPOSCAR_{q}_{irrep}_{direction}_{spacegroup}; when one q point carries two imaginary levels of the same irrep, the second gains a _mode{n} suffix (n = its first mode number) so the two sets do not overwrite each other.

  • The combination of the degenerate modes behind each direction is measured (the space group of each generated structure), not assumed. A direction that no candidate reproduces is reported, never guessed at; generate it with --modulation by hand:

  note: no candidate reproduced M5-(0,0;a,0;0,a) (I4/mmm); generate it with --modulation by hand.

Every enumerated row therefore ends up either as a file or as a note. The directions that need a note belong to large order parameters (a multi-arm star times a degenerate level): for X5- of cubic ScF3 (three arms times a pair) the six-component directions such as X5-(a,a;a,a;a,a) (R-3c) are among them.

A star with several arms
