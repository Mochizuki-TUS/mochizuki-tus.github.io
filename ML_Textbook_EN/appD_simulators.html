Appendix DComputational Specifications of the Simulators and Records of Checks

The chapters of this book embed ten simulators, in which you move parameters and watch the results. This appendix records, so that readers can judge for themselves, what each simulator computes (the formulas and algorithms) and how far it has been checked (against what, how many cases, and with what tolerance). Before you quote a number shown on a simulator's screen in a report or in research, please read the relevant section.

Section D.1 describes the design common to all simulators (operating environment, random numbers, display of equations, embedding, computation limits), and Sections D.2–D.11 list the same items for each simulator in turn. Section D.12 summarizes what has not been checked and the known limitations. “Checked” as written here refers only to the tests actually run on November 12–13, 2026. It does not guarantee correct behavior under conditions not described here (other browsers, other devices, parameter combinations not included in the tests).

The checking methods are divided into the following four kinds. Analytical solution: comparison with quantities that are determined by a closed-form expression or a hand calculation. Full enumeration: comparison with the value obtained by counting all possible cases. Independent implementation: comparison with the value computed for the same quantity by a Python program (NumPy, SciPy, PyTorch, and so on) written independently of the simulator. Statistical check: a test, with a stated tolerance, of whether a quantity that uses random numbers follows the theoretical distribution. Writing $a$ for the value being compared (the simulator) and $b$ for the reference, the tolerance takes the form $\abs{a-b}\le \mathrm{atol}+\mathrm{rtol}\,\abs{b}$ (absolute tolerance atol, relative tolerance rtol).

D.1.2 Operating environment and communication with the outside

  • The simulators run on static HTML, CSS, and JavaScript only. Each simulator consists of a file for the screen (sim/NAME.html), a file containing only the computation (sim/NAME.model.js, pure functions that do not touch elements of the screen), a shared numerical computation library (sim/lib/mlcore.js), and shared screen components (sim/lib/mlui.js, sim/lib/mlsim.css). Only S10 also reads the trained weights (sim/data/tinygpt.js) and the table of the bigram model (sim/data/tinygpt_bigram.js).
  • The computation was separated from the screen so that the same computation file can be run as it is in Node.js and compared numerically with a Python reference computation (the tests of D.1.7). The scripts use only the classic loading by <script src>, so they are built to work even when the file is opened directly (file://) without starting a server. We checked that there are no console errors when opening with file:// for all ten simulators, but only S09 and S10 were operated through the whole script over file://; for the other eight, only the display right after opening was checked (Table D.3, D.12).
  • No external inference API, API key, external font, or CDN is used. The small model of S10 also computes its forward propagation inside the browser (it does not query a server). The scripts of the simulators contain neither commands that communicate (fetch, XMLHttpRequest, and so on) nor storage in the browser (localStorage, and so on). The values you enter are not sent outside and do not remain after the page is closed. The only thing sent to the parent page when embedding is the display height (in pixels).
  • The chapter pages (the main text) load MathJax from a CDN to display equations, but the simulator pages do not.

D.1.3 Random numbers

  • All simulators use only mulberry32 (a small pseudorandom number generator with a 32-bit state) as the random number generator. The seed is rounded to a 32-bit unsigned integer. Gaussian random numbers are generated by the Box–Muller method, gamma random numbers by the Marsaglia–Tsang method, and Poisson random numbers by the product method when the mean is below 30 and by the PTRS method when it is 30 or above. The browser's built-in Math.random is not used.
  • The simulators that use random numbers have a “Random-number seed” field in which you can enter an integer, along with the buttons “Rerun with same seed,” “Change seed” (adds 1), and “Reset to default.” In the same browser, the same seed and the same order of operations give the same result (in the tests we checked the reproducibility with a fixed seed for each simulator). To reuse the sequence of random numbers from the beginning, press “Rerun with same seed.”
  • Exception: Gaussian random numbers pass through Math.log, Math.cos, and Math.sin, so the values may differ between Node.js and Chrome by just 1 ulp (one unit in the last place, the least significant digit of double precision). The difference is normally not visible in the displayed digits, but in an ill-conditioned iterative computation the result changes slightly. An example recorded at the time of writing: for the SVM of S04 (linear kernel, overlapping data, $C=1000$), the number of SMO iterations to convergence was 7,614 in Chrome and 7,583 in Node.js (this difference was not checked again). For S07, the values on screen and in Node.js were treated as agreeing to the fifth digit.

D.1.4 Display of equations

The equations on the simulators' screens are written in the browser's standard MathML (MathJax is not used). Therefore they look slightly different from the equations in the main text (for example, the transpose is $\tp$ in the main text but T on screen), but the choice of symbols matches the main text. Many simulators have a panel “Putting the current numbers into the formula,” which displays the formula with the numbers of the current settings substituted. Boldface within equations is specified with MathML mathvariant="bold-italic" to match the main text's $\bm{x}$ ("bold" for capital Greek letters and digits), and so that it also appears bold in Chrome, which does not reflect this specification, a bold typeface is specified in the stylesheet common to the simulators. Calligraphic and blackboard bold are written with mathematical characters (𝒩, 𝒟, ℬ, 𝔼) without using mathvariant. Boldface in explanatory text outside the equations (<b>) is upright bold, and its shape differs slightly from the bold italic of the main text. How MathML looks in browsers other than Chrome has not been checked.

D.1.6 Computation limits, behavior on errors, and when JavaScript is disabled

  • All inputs have limited ranges (the minimum and maximum of sliders; numeric fields are rounded into the range). The range and upper limit of each simulator are given in D.2–D.11.
  • Time-consuming computations (the evolution of the sample mean in S01, the bias and variance in S03, the comparison in S06, and so on) are divided into pieces of at most 12 ms per frame and advanced little by little, so that you can press “Stop.” No simulator keeps running a computation automatically just because it has been opened.
  • When NaN (not a number) or ∞ appears during a computation, the computation is stopped and a sentence on screen says what happened. The same applies when training diverges (S04, S05).
  • All operations are done with buttons, sliders, selection fields, and numeric fields, and can also be done from the keyboard (tabs move with ←, →, Home, and End). Each figure (canvas) is given a sentence describing the state at that moment (aria-label), which is updated every time the figure is drawn. We do not rely on color alone: line styles, marker shapes, and the text beside the curves also distinguish them.
  • When JavaScript is disabled, the interactive part and the figures are not displayed. In that case a notice, “The interactive part does not work,” and a link to the section of the main text are displayed, and the explanation below (procedure, the formulas being computed, conditions of the data and random numbers, simplifications, conditions for instability, questions) is static HTML and can be read as it is. The boxes embedded in the main text carry a notice to the same effect.

D.1.7 How the checks were carried out

  • Numerical tests (Node.js): The computation file of each simulator and the shared library were run in Node.js (v25.9.0) and compared with reference values computed separately in Python (NumPy 2.5.4, SciPy 1.18.1; CPU, double precision). For S05 the automatic differentiation of PyTorch (double precision) was also used as a reference, for S06 mpmath (50 digits), and for S10 the PyTorch model used for training (single precision). All computations of the simulators are in double precision (JavaScript numbers).
  • Statistical checks: Quantities that use random numbers were evaluated only once with a fixed seed, and the tolerance was set to a size at which “a correct generator passes.” As a guide, about 4 standard errors; for the Kolmogorov–Smirnov test (hereafter, KS test), the statistic $D\lt 1.95/\sqrt{n}$ (significance level about 0.1 %); and for the $\chi^{2}$ test, the upper 0.1 % point. We did not reselect seeds to suit the tests, nor widen the tolerances afterward.
  • Independent recomputation: Separately from the tests, the main values of each simulator (including the numbers appearing in the procedures of the boxes in the main text) were recomputed with Python programs (NumPy and SciPy; mpmath as well for S06) rewritten without looking at the reference computation of the tests, and compared with the values of the computation file. The differences were sufficiently smaller than the displayed digits. There were two exceptions: for the SVM of S04, because of the stopping tolerance $\varepsilon=10^{-3}$, the margin width and similar quantities differed from the reference in the fourth digit (relative difference at most $3.6\times10^{-4}$), and for the EI and PI of S06, the values differed from the reference in the tail beyond $z\approx-20$ (D.7.5).
  • Screen checks: In headless Chrome (desktop version), we opened the screens at widths of 390, 768, and 1280 px (for S10 also 310 and 352 px, which correspond to the chapter's frame), operated them according to the script (boundary values, starting over, all tabs, ?embed=1, ?only=, keyboard operation, the procedures in the boxes of the main text), and compared the numbers on the screen with the Node.js values (the “comparisons” in the script). At the same time, we confirmed that no horizontal scrolling of the page appears and that console errors and loading failures are zero, and we looked at some of the captured images by eye and fixed overlapping text and the like.
  • The shared numerical computation library itself was also checked with 685 tests: special functions (the log-gamma function, the regularized incomplete gamma and beta functions and their inverses, the error function, the cumulative distribution function and quantile of the Gaussian distribution, log-sum-exp, softmax, and so on) with 347 tests against SciPy's special, probability distributions with 264 tests against SciPy's stats, linear algebra (Cholesky decomposition, QR decomposition, least squares, eigendecomposition of symmetric matrices, SVD, and so on) with 28 tests against NumPy's linalg, statistical functions with 14 tests against NumPy, and 5 tests of random-number reproducibility and 27 tests of sample statistics. All succeeded.

D.2 S01 Probability Distributions (distributions)

D.2.1 Corresponding chapters, sections, and tabs

  • Chapter 3: Section 3.5 (Simulator 3.1, tab shape), Section 3.7 (Simulator 3.2, tab mean). It is also related to Sections 3.1, 3.2, 3.4, and 3.8–3.10, and to Chapter 2, Section 2.8 (law of large numbers).
  • Tab shape, “① Distribution Shape and Interval Probability”; tab mean, “② Behavior of the Sample Mean”.

D.2.2 What is computed

  • ①: For eight distributions (binomial, Poisson, Gaussian, Cauchy (Lorentzian), gamma (shape $a$, rate $b$), beta, Student's t (location $\mu$, scale $s$), and Weibull), the simulator computes the probability density (mass) function, the cumulative distribution function $F$, quantiles, the mean and variance (if they do not exist, it displays “does not exist” together with the reason), the median, the mode, and the full width at half maximum. When there are two modes (when $\lambda$ of the Poisson distribution is an integer, or when $(N+1)\mu$ of the binomial distribution is an integer; example: 3 and 4 for $\lambda=4$), both are displayed as “maximal with equal probability”. The interval probability is obtained from $$P(x_1\le x\le x_2)=F(x_2)-F(x_1)$$ (for a discrete distribution the endpoint integers are included). The cumulative distribution function is computed with the error function, the regularized incomplete gamma and beta functions, the arctangent, and so on; in the “Check” line on the screen, the direct sum of the probability mass function is shown for discrete distributions, and the double-exponential numerical integration of the probability density function for continuous distributions.
  • As the reason why the mean does not exist for the Cauchy distribution (and for the t distribution with $\nu=1$), the simulator shows with the numbers $R=10\gamma,100\gamma,1000\gamma$ that $\int_{x_0-R}^{x_0+R}\abs{x-x_0}\,p(x)\,\dd x$ $=(\gamma/\pi)\ln(1+R^{2}/\gamma^{2})$ keeps growing with $R$.
  • The samples (histogram) are drawn from the first distribution. The Gaussian uses the Box–Muller method; the Cauchy uses $\tan(\pi(u-1/2))$; the t uses $z/\sqrt{g/\nu}$ ($z$ is a standard Gaussian random number and $g$ is a $\chi^{2}$ random number with $\nu$ degrees of freedom); the gamma uses the Marsaglia–Tsang algorithm; the binomial uses a sum of Bernoulli variables; and the Poisson uses the product method or the PTRS algorithm.
  • ②: From independent samples of the Gaussian, Cauchy, and t distributions, the simulator draws the evolution of the sample mean $\bar{x}_n$ (or the median) against the number of samples $n$ for several sequences (the horizontal axis is logarithmic; the number of recorded points is 151/180/197 for the upper limits of $n$ of $10^{3}$/$10^{4}$/$10^{5}$). For the Gaussian (and the t distribution with $\nu\gt 2$) a band of $\pm\sigma/\sqrt{n}$ is overlaid; for the Cauchy distribution, lines at the center $\pm\gamma$ (the half width at half maximum of the distribution of $\bar{x}_n$ does not depend on $n$); and for the median, a band given by the asymptotic formula $\pm1/(2p(m)\sqrt{n})$.

D.2.3 Input ranges, upper limits, and random numbers

  • Parameter ranges (defaults in parentheses): binomial $N$ 1–200 (20), success probability 0–1 (0.3); Poisson $\lambda$ 0.1–60 (4); Gaussian $\mu$ −5 to 5, $\sigma$ 0.1–5 (defaults $\mu=0$, $\sigma=1$); Cauchy $x_0$ −5 to 5 (0), $\gamma$ 0.1–5 (1); gamma $a$ 0.2–20 (2), $b$ 0.1–10 (1); beta $a,b$ 0.2–20 (2, 5); $\nu$ of the t distribution is chosen from 17 values between 0.5 and 1000 (including 1 and 2 exactly; default 3), $s$ 0.1–5; Weibull $m$ 0.5–30 (5), $s_0$ 0.2–5 (1).
  • The number of samples in ① is none/100/1000/10000, and the upper limit is 10000 samples (the upper limit of the calculation file is also 10000). The $n=20000$ of the KS test and the $\chi^{2}$ test in D.2.6 comes from tests that called the calculation file directly; it cannot be selected on the screen. In ②, the upper limit of $n$ is $10^{3}$/$10^{4}$/$10^{5}$, the number of sequences is 1–20, and the scale is 0.2–3 (the location is fixed at 0). In the largest case, $10^{5}\times20$ sequences × 2 distributions $=4\times10^{6}$ random numbers are computed in chunks of 12 ms each (about 0.56 s in Chrome).
  • The default seed is 20261112 for both ① and ②. The seed of sequence $j$ in ② is seed $+\,j\cdot$0x9E3779B9, so the initial part of each sequence is the same even if the upper limit of $n$ or the number of sequences is changed. The 1000 Cauchy samples in ① and the first 1000 samples of sequence 1 of the Cauchy distribution in ② take the same values.

D.2.4 Simplifications

  • The parameter ranges are restricted, and $\nu$ of the t distribution is chosen from 17 values.
  • The histogram in ① counts only the samples inside the plotted range (the number outside the range is displayed).
  • In ②, the location is fixed at 0, and the scale takes a common value for the three distributions (the full widths at half maximum are not matched). The median band is an asymptotic approximation.
  • No example comparing the binomial distribution with its Gaussian approximation is provided (because it does not fit within the range −5 to 5 of the Gaussian $\mu$).

D.2.5 Conditions for instability and the behavior of the simulator

  • For the Cauchy distribution and for the t distribution with $\nu\le 2$, samples with very large values (of the order of $10^{5}$–$10^{7}$) appear, and the sample mean and sample variance jump. This is not a calculation error but a property of the distribution, and the simulator displays it as it is.
  • For the gamma distribution with $a\lt 1$, the beta distribution with $a\lt 1$ or $b\lt 1$, and the Weibull distribution with $m\lt 1$, the density diverges at an endpoint. The figure is clipped by the frame, and the numerical-integration “Check” deviates by up to about $10^{-8}$ at the endpoint because of the limits of double precision.
  • When the vertical axis is logarithmic, values below $10^{-300}$ are rounded to 0 and the line is cut.
  • If NaN or ∞ appears, the calculation is stopped and the reason is displayed.

D.3 S02 Bayesian Updating (bayes-update)

D.3.1 Corresponding chapters, sections, and tabs

  • Chapter 4: Section 4.5 (Simulator 4.1, tab beta), Section 4.8 (Simulator 4.2, tab gauss). Also Section 4.4 and Section 4.6.
  • Tab beta “① Beta–Bernoulli (success rate)”, tab gauss “② Mean of a Gaussian”.

D.3.2 What is computed

  • ①: After observing $m$ successes and $l$ failures ($N=m+l$), the prior distribution $\mathrm{Beta}(\mu\mid a,b)$ becomes the posterior distribution $\mathrm{Beta}(\mu\mid a+m,\,b+l)$. The simulator shows the maximum likelihood estimate $m/N$, the MAP estimate $(a+m-1)/(a+b+N-2)$ (when $a+m\gt1$ and $b+l\gt1$), the posterior mean $(a+m)/(a+b+N)$ (= the posterior prediction $p(x=1\mid\data)$), the posterior standard deviation, the 95 % credible interval (equal-tailed; found with the inverse of the regularized incomplete beta function), and the data weight $w=N/(a+b+N)$.
  • The likelihood in the figure is drawn with its area normalized to 1 (the same shape as $\mathrm{Beta}(\mu\mid m+1,l+1)$). “Compare sequential and batch updates” compares the sequence of parameters updated one observation at a time, and the density obtained by multiplying numerically one observation at a time on a grid of 2001 points, with the batch analytical solution.
  • ②: With the noise variance $\sigma^{2}$ known, from the prior distribution $\Normal(\mu\mid\mu_0,\sigma_0^{2})$ it finds $$\begin{aligned}\frac{1}{\sigma_N^{2}}&=\frac{1}{\sigma_0^{2}}+\frac{N}{\sigma^{2}},\\ \mu_N&=\sigma_N^{2}\left(\frac{\mu_0}{\sigma_0^{2}}+\frac{N\bar{x}}{\sigma^{2}}\right)\end{aligned}$$ and displays the variance of the posterior predictive distribution split into $\sigma^{2}$ (noise) and $\sigma_N^{2}$ (lack of knowledge).

D.3.3 Input ranges, upper limits, and random numbers

  • ①: $a,b$ range over 0.5–30 (in steps of 0.5; default 1, 1), the true $\mu$ over 0.01–0.99 (default 0.70), and up to 2000 observations. ②: $\mu_0$ from −3 to 3 (0.0), $\sigma_0$ 0.1–3 (2.00), $\sigma$ 0.2–3 (1.00), the true $\mu$ from −3 to 3 (1.5), and up to 1000 observations.
  • Synthetic data (synthetic data for teaching purposes; dimensionless): in ① a uniform random number $u\lt\mu$ counts as a success; in ② $x=\mu+\sigma\varepsilon$ with $\varepsilon\sim\Normal(0,1)$. The default seed is 20261112. Changing the seed clears the observations and draws them again.

D.3.4 Simplifications

  • The observations are assumed independent and $\mu$ constant. In ② the noise variance is assumed known (if it were unknown, the posterior predictive distribution would be a Student's t distribution).
  • The credible interval is an equal-tailed interval, not a highest-density interval. The ranges of the parameters are restricted.

D.3.5 Conditions for instability and the behavior of the simulator

  • When $a+m\lt1$ or $b+l\lt1$, the density diverges at an endpoint and has no interior maximum, so no MAP estimate is given and the reason is displayed. When $a+m=1$ or $b+l=1$ (with the other greater than 1), the maximum is at an endpoint and agrees with the value from the formula; a note to this effect is shown (example: with a uniform prior and 3 successes in 3 trials, the MAP estimate is 1).
  • When $N=0$, the maximum likelihood estimate is undefined (it is not displayed). When the posterior distribution is uniform ($a+m=b+l=1$; for example Beta(1,1) left as it is with $N=0$), the MAP estimate is displayed as “not uniquely determined”.
  • When $N$ is large, the peak of the density becomes sharp and the vertical axis stretches, but the computation is done with logarithms, so no overflow occurs.

D.4.2 What is computed

  • The data are Data A of Chapter 6 (synthetic data for teaching purposes): $s=(T-1300\ ^{\circ}\mathrm{C})/(200\ ^{\circ}\mathrm{C})\in[-1,1]$, $y=88+8s-5s^{2}+2\sin 3s+\varepsilon$ (relative density in %), $\varepsilon\sim\Normal(0,\sigma^{2})$.
  • ①: With a polynomial of degree $d$ (basis functions $\phi_j(s)=s^{j}$, $j=0,\dots,d$, giving $M=d+1$ of them, $\bm{\Phi}\in\R^{N\times M}$), the simulator minimizes $$L(\bm{w})=\tfrac12\norm{(\bm{y}-88)-\bm{\Phi}\bm{w}}^{2}+\tfrac{\lambda}{2}\norm{\bm{w}}^{2}$$ for $\bm{y}-88$, the target values with the fixed baseline value 88 % subtracted. For $\lambda=0$ it solves by Householder QR decomposition, and for $\lambda\gt0$ by QR decomposition of $[\bm{\Phi};\sqrt{\lambda}\bm{I}]$ (no inverse matrix is formed). When $d+1\gt N$ and $\lambda=0$, the solution is not unique, so the minimum-norm solution by SVD is used and this is displayed. It displays the RMSE $=\sqrt{(1/N)\sum_n(y_n-f(s_n))^{2}}$ on the training data and on the validation data (200 separate points from the same distribution), the RMSE against the true function, and the condition number of $\bm{\Phi}$.
  • ②: From the mean $\bar{f}(s)$ of the curves $f^{(l)}(s)$ fitted to $L$ training data sets, it finds $(\text{bias})^{2}=\langle(\bar f-g)^{2}\rangle_s$, the variance $=\langle(1/L)\sum_{l=1}^{L}(f^{(l)}-\bar f)^{2}\rangle_s$, and the noise $\sigma^{2}$ ($\langle\cdot\rangle_s$ is the midpoint rule with 200 points on $[-1,1]$, and $g$ is the true function). The sweep over $\lambda$ is solved by SVD, and the mean and variance are updated sequentially, one data set at a time.
  • ③: Under the prior distribution $p(\bm{w})=\Normal(\bm{w}\mid\bm{0},\sigma_w^{2}\bm{I})$, it uses $\bm{S}_N^{-1}=\sigma_w^{-2}\bm{I}+\sigma^{-2}\bm{\Phi}^{\tp}\bm{\Phi}$ and $\bm{m}_N=\sigma^{-2}\bm{S}_N\bm{\Phi}^{\tp}\bm{y}$ (the target value is again $y-88$), and the prediction $\Normal(y_*\mid\bm{m}_N^{\tp}\bm{\phi}_*,\ \sigma^{2}+\bm{\phi}_*^{\tp}\bm{S}_N\bm{\phi}_*)$. The band of lack of knowledge $\pm2(\bm{\phi}^{\tp}\bm{S}_N\bm{\phi})^{1/2}$ and the band of observed values $\pm2(\sigma^{2}+\bm{\phi}^{\tp}\bm{S}_N\bm{\phi})^{1/2}$ are drawn separately. The basis is either polynomial (degree $d$) or nine Gaussian basis functions (centers $c_j=-1,-0.75,\dots,1$, width $r=0.25$, no constant basis function).

D.4.3 Input ranges, upper limits, and random numbers

  • ①: number of training data points $N$ 5–50 (10), noise standard deviation 0–3 % (1.0), degree $d$ 0–12 (3), $\ln\lambda$ from −20 to 4 (“no regularization” is the default).
  • ②: degree 0–12 (9), $\ln\lambda$ from −14 to 4 (−3.0), $N$ of one data set 5–50 (15), noise 0.2–3 %, number of data sets $L$ 10–200 (100). The computation is split so that each frame takes at most 12 ms (measured with Node.js: about 20–25 ms for the default, about 150 ms for the largest setting).
  • ③: the $\sigma$ assumed by the model 0.05–5 % (1.00), $\sigma_w$ 0.1–100 (10.0), up to 100 observation points (8 initially), the point of interest $s_*$ from −1.4 to 1.4 (1.20), and 0–10 function samples from the posterior distribution. The noise of the points drawn with “Draw from Data A” is fixed at 1.0 % (separate from the model's $\sigma$).
  • The default seed is 20261112. Points are drawn one at a time (in the order $s$ then $\varepsilon$), so with the same seed the earlier points remain when $N$ is increased. The validation data use the random-number sequence of seed + 1000003, and the samples in ③ use the sequence of seed + 7 (plus 101 each time they are redrawn).

D.4.4 Simplifications

  • The fixed baseline value 88 % is subtracted from the target values, and a penalty (in ③, the prior distribution) is applied to all coefficients, including the intercept $w_0$. In practice the intercept is often not penalized, and in that case $\lambda$ acts slightly differently (this is noted in Chapter 8). The value 88 % is not computed from the data.
  • Bias$^{2}$ is estimated from a finite number $L$ of data sets, so it contains an error of about variance$/L$.
  • The $\sigma$ and $\sigma_w$ in ③ are given values, and the marginal likelihood is not maximized. The basis consists of monomials; orthogonal polynomials are not used.

D.4.5 Conditions for instability and the behavior of the simulator

  • At high degrees without regularization, the condition number of $\bm{\Phi}$ becomes $10^{4}$–$10^{8}$ ($2.33\times10^{4}$ for $N=10$, $d=9$). When $d+1\gt N$ and $\lambda=0$, the solution is not unique, so the minimum-norm solution and a cautionary note are displayed.
  • In ②, with no regularization and small $N$, the variance exceeds $10^{10}$ and is cut off at the top of the figure ($4.7\times10^{18}$ for $N=15$, $d=12$).
  • In ③, if $\sigma$ is made small, $\sigma_w$ large, and $d=12$, the predictive mean swings to about −1400 % in extrapolation (the numbers remain finite and the computation does not stop, but they fall outside the figure). With Gaussian basis functions, far from the centers of the basis functions $\bm{\phi}\approx\bm{0}$, and the band of lack of knowledge approaches 0 (the band becomes narrow even though the point is far from the data; this is due to the assumption in how the basis is placed).
  • If NaN or ∞ occurs, the computation stops and the reason is displayed.

D.5.2 What is computed

  • ①: With the features $\bm{\phi}(\bm{x})$ (first order $(x_1,x_2)$, or with the quadratic terms $x_1^{2},x_1x_2,x_2^{2}$ added) and $a_n=\bm{w}^{\tp}\bm{\phi}(\bm{x}_n)+b$, we add a regularization term to the sum of the cross-entropies, $$\begin{aligned}L(\bm{w},b)&=\sum_{n=1}^{N}\bigl[\ln(1+e^{a_n})-y_na_n\bigr]\\ &\quad+\tfrac{\lambda}{2}\norm{\bm{w}}^{2}\end{aligned}$$ ($b$ is not regularized), and reduce it by gradient descent starting from $\bm{w}=\bm{0}$, $b=0$. $\ln(1+e^{a})$ is computed in a form that does not overflow. As a guide to the stability of the learning rate, the simulator displays $2/L_c$ (where $L_c=\lambda_{\max}(\tilde{\bm{\Phi}}^{\tp}\tilde{\bm{\Phi}})/4+\lambda$ and $\tilde{\bm{\Phi}}$ is the matrix obtained by adding a column of constant 1 to the features), and, for comparison, the minimum $L^{*}$ found by Newton's method. When the minimum is not attained at any finite weights (for example, linearly separable data with $\lambda=0$), the simulator reports this through the Newton's method check.
  • ②: It solves the dual problem of the SVM with a kernel (linear $\bm{x}^{\tp}\bm{x}'$, polynomial $(\bm{x}^{\tp}\bm{x}'+1)^{2}$ and $(\bm{x}^{\tp}\bm{x}'+1)^{3}$, RBF $\exp(-\gamma\norm{\bm{x}-\bm{x}'}^{2})$ with $\gamma=1/(2\ell^{2})$), $$\begin{aligned}\max_{\bm{\alpha}}\ &\sum_n\alpha_n-\tfrac12\sum_{n,m}\alpha_n\alpha_m y_ny_m k(\bm{x}_n,\bm{x}_m),\\ &0\le\alpha_n\le C,\qquad \sum_n\alpha_ny_n=0\end{aligned}$$ by the SMO algorithm. Each time a parameter is changed, the problem is solved again from $\bm{\alpha}=\bm{0}$, and the stopping criterion is $m(\bm{\alpha})-M(\bm{\alpha})\le\varepsilon=10^{-3}$. It draws $f(\bm{x})=\sum_n\alpha_ny_nk(\bm{x}_n,\bm{x})+b$, and $b$ is obtained from the free support vectors ($0\lt\alpha_n\lt C$; if there are none, the midpoint is used). The screen states that $f(\bm{x})$ is “a score, not a probability.” The simulator also displays the residual of the KKT conditions, the dual objective function $D$, the value $P$ of the primal problem, and the duality gap.

  • Common to both tabs: the data type (linearly separable / overlapping / concentric circles / two moons / XOR; synthetic data for teaching purposes; the two descriptors are standardized, dimensionless values), the number of data points $N$ from 10 to 200 (in steps of 2; default 60), and up to 300 points including points added by clicking. The default seed is 20261112 (both tabs).

  • ②: $C$ from 0.01 to 1000 (default 1.00), $\gamma$ from 0.01 to 100 (default 1.00), and an upper limit on SMO iterations from 10 to 100,000 (default 100,000).
  • The sliders for $\gamma$ and $C$ move in steps of 0.05 in $\log_{10}$, so they do not land exactly on round values. The displayed “20.0” is $\gamma=10^{1.3}=19.953$, “0.0501” is $10^{-1.3}$, and “5.01” is $10^{0.7}$ (the $C$ value “1000” is exactly $10^{3}$). Likewise $\eta$ cannot be set to 0.3 and becomes 0.32. D.5.4 Simplifications

  • The inputs are taken to be standardized from the start, and the quadratic terms are not standardized (which is why the stable $\eta$ becomes small). Because the loss is a sum rather than a mean, the stable learning rate depends on $N$.
  • Only full-data gradient descent is provided (no minibatches). $b$ is not regularized. The only evaluation is the training accuracy (no validation or cross-validation).
  • SMO uses neither shrinking nor a cache of kernel values. The conversion of scores to probabilities (Platt scaling) is not performed. The constant of the polynomial kernel is fixed at 1, and the RBF kernel uses $\sigma_f=1$.

D.5.5 Conditions for instability and the behavior of the simulator

  • For $\eta\gt2/L_c$, the loss oscillates or increases. The simulator stops when $\norm{\bm{w}}\gt10^{6}$ or on NaN, and displays the reason (convergence can still occur beyond the guide value; the guide value is a sufficient condition).
  • If the data are linearly separable with $\lambda=0$, there is no minimum and $\norm{\bm{w}}$ keeps growing (the simulator displays “not at finite weights”). With data of only one class, $b$ diverges.
  • The SVM needs at least one point in each of the two classes, and if this is not satisfied the simulator displays the reason. With the linear kernel, overlapping data, or a large $C$, SMO is slow, and when it reaches the upper limit the simulator displays “this solution is not optimal.” For a large $C$, the duality gap $P-D$ remains rather large even when $m-M$ is small.
  • When points with opposite labels lie at the same position (the quadratic coefficient of SMO is 0), the algorithm avoids this with a small value ($10^{-12}$) and still converges (confirmed by the tests).
  • Because of the stopping tolerance $\varepsilon=10^{-3}$, the number of support vectors may differ by one from that of the exact dual solution. Example: for the overlapping data with RBF $\gamma=1$ and $C=1$, the screen shows 35 (16 ○, 19 ◇), but one of them is a leftover with $\alpha_n=1.7\times10^{-3}$, and in the exact solution there are 34. $D$, the margin width, and the accuracy agree to the displayed digits. The same thing happens depending on the order in which points are added (if the order is changed in the three-point example of Chapter 11, a leftover of $\alpha_n=2.4\times10^{-4}$ remains, giving three support vectors and a width of 2.001).
  • For ill-conditioned problems, the number of SMO iterations changes slightly depending on the environment because of a 1 ulp difference in the random numbers (D.1.3).

D.6.2 What is computed

  • A network with one hidden layer and one output: $\bm{a}^{(1)}=\bm{W}^{(1)}\bm{x}+\bm{b}^{(1)}$, $\bm{z}^{(1)}=h(\bm{a}^{(1)})$, $a^{(2)}=\bm{W}^{(2)}\bm{z}^{(1)}+b^{(2)}$, $\hat{y}=\sigma(a^{(2)})$ (classification) or $\hat{y}=a^{(2)}$ (regression). Backward propagation is $$\begin{aligned}\delta^{(2)}&=\hat{y}-y,\\ \bm{\delta}^{(1)}&=h'(\bm{a}^{(1)})\odot\bigl(\bm{W}^{(2)\tp}\delta^{(2)}\bigr),\\ \pdiff{L}{\bm{W}^{(l)}}&=\bm{\delta}^{(l)}\bm{z}^{(l-1)\tp},\qquad \pdiff{L}{\bm{b}^{(l)}}=\bm{\delta}^{(l)}\end{aligned}$$ (with $\bm{z}^{(0)}=\bm{x}$).

For classification, $\ell$ is the cross-entropy (computed in the form $\ln(1+e^{a})-ya$); for regression, $\ell$ is $\tfrac12(\hat{y}-y)^{2}$. Training uses plain stochastic gradient descent. The regression target values are standardized with the mean and standard deviation of the training data (the loss is in standardized units, and the RMSE is displayed in %). The initial values are Xavier for tanh and sigmoid (variance $2/(\text{number of inputs}+\text{number of outputs})$) and He for ReLU ($2/\text{number of inputs}$); the output layer uses Xavier, and the biases are 0. “All 0” can also be selected.
  • ③: For all parameters, the gradient from backward propagation is compared with finite differences (central difference and forward difference), and the V shape of the error as a function of the step size $\epsilon$ is plotted. Pass or fail is decided by “the relative error as a vector, $\norm{\bm{g}-\hat{\bm{g}}}/\max(\norm{\bm{g}},\norm{\hat{\bm{g}}})\le10^{-6}$”.

  • With a sigmoid hidden layer the gradients tend to become small, and with ReLU some units get stuck with output 0. In classification, if the classes can be separated perfectly, the weights keep growing when $\lambda=0$.
  • If the initial values are all 0, the symmetry is not broken (with tanh the weights stay at 0 and only the bias $b^{(2)}$ moves).
  • If XOR is trained with two hidden units, the default seed, and $\eta=0.1$, training stays at a local solution with an accuracy of 75 % (with four hidden units it reaches 100 %). Being able to represent a function and being able to find it by training are different things (Chapter 14).

Gradient components close to 0 can show a large componentwise relative error (example: $4.6\times10^{-6}$ for a component of magnitude $3.8\times10^{-6}$), so the decision is based on the relative error as a vector. For an $\epsilon$ that straddles the kink of ReLU, the finite difference does not become the derivative.

If rounding makes $\sigma_*^{2}\lt0$, it is clipped to 0 and the number of such cases is displayed. By grid search, $\ell$ (41 points) or $\ell,\sigma_f,\sigma$ ($41\times13\times21=11193$ combinations) can be chosen so as to maximize the log marginal likelihood.
  • ②: The acquisition function is evaluated at 401 points (in steps of 0.025 mol%), and the point with the maximum value is observed next (if values are equal, the one with the smaller $x$). For maximization, $$\begin{aligned}\mathrm{EI}&=(\mu_*-f_{\mathrm{best}}-\xi)\,\Phi(z)+\sigma_*\Normal(z\mid0,1),\\ z&=\frac{\mu_*-f_{\mathrm{best}}-\xi}{\sigma_*},\\ \mathrm{PI}&=\Phi(z),\qquad \mathrm{UCB}=\mu_*+\kappa\sigma_*\end{aligned}$$ (for $\sigma_*=0$, $\mathrm{EI}=\max(\mu_*-f_{\mathrm{best}}-\xi,0)$); for minimization (minimizing $-y$), LCB $=\mu_*-\kappa\sigma_*$ and the EI with the sign changed are used. For $f_{\mathrm{best}}$ one can choose either the best observed value or the best posterior mean at the observation points.
  • ③: With the same budget, Bayesian optimization, random search, and an equally spaced grid are repeated, and the median and interquartile range of the simple regret $r_n=y_{\max}-y(\hat{x}_n)$ are drawn ($\hat{x}_n$ is the point with the largest observed value up to the $n$th evaluation, and $y(\hat{x}_n)$ is the true value at that point). For the grid, for each number of evaluations $n$, we measure the grid that one would place for a budget of $n$, namely $x_k=10(k-\tfrac12)/n$.

  • The maximization of the acquisition function is done on a grid of 401 points. The hyperparameters are either fixed or chosen only by grid search (no gradient method or prior distribution is used). The recommended point is the point with the largest observed value.

D.7.5 Conditions for instability and the behavior of the simulator

  • When $\sigma$ is small and $\ell$ is large, or when observations at the same $x$ coincide, $\bm{K}_y$ becomes nearly singular. The simulator adds jitter, continues the computation, and writes that amount on the screen (the tests confirm that jitter is added when $\sigma=0$ and there are two observations at the same $x$).
  • With few observations, the maximum of the marginal likelihood may be flat or stick to the end of the range (in the example 8 points, $\sigma$ sticks to the lower end 0.005).
  • When $\ell$ is long and $\sigma$ is small, EI and PI become 0 everywhere. In that case the left end of the grid is chosen, and a warning is shown in red.
  • The cumulative distribution function $\Phi(z)$ of the standard Gaussian distribution in the shared library has a relative error of about 0.4 % in the tail beyond $z\approx-20$, and the EI there (about $10^{-123}$) differs from the mpmath value by 3 % in relative terms. This does not affect the numbers shown on the screen, but in settings where EI is below $10^{-100}$ everywhere ($\ell=10$ with small $\sigma$, for example), the chosen point is determined by rounding. When the 1331 points chosen by Bayesian optimization in the comparison ③ were recomputed with NumPy, only 6 differed (4 were differences in how a value was chosen among equal values, because the marginal likelihood used to choose $\ell$ was flat; 2 were cases where EI was below $10^{-300}$ at all points).
  • Because of the observation noise, the simple regret may increase even as the number of evaluations increases (in the default ②, at the 10th and 16th evaluations).
  • If we fix $\ell=10$, Bayesian optimization loses to random search (with budget 30 and 200 repetitions, medians 0.0488 versus 0.0186). If $\ell$ is chosen by the marginal likelihood each time, it does not lose.
  • For NaN and ∞, the computation stops and the reason is displayed.

D.8.2 What is computed

  • ① (EM algorithm for a Gaussian mixture, two dimensions): The E step computes the responsibilities $$\gamma_{nk}=\frac{\pi_k\Normal(\bm{x}_n\mid\bm{\mu}_k,\bm{\Sigma}_k)}{\sum_{j}\pi_j\Normal(\bm{x}_n\mid\bm{\mu}_j,\bm{\Sigma}_j)}$$ and the M step updates $N_k=\sum_n\gamma_{nk}$, $\pi_k=N_k/N$, $\bm{\mu}_k$, and $\bm{\Sigma}_k$; the simulator plots the progression of the log-likelihood $\ln p(\bm{X}\mid\bm{\theta})$. The Gaussian density is computed with a 2 × 2 Cholesky decomposition. When the “variance floor” is on, the eigenvalues of $\bm{\Sigma}_k$ in the M step are raised to $\max(\lambda,c)$ (the eigenvectors are left unchanged; since this is the maximum-likelihood solution under the constraint “eigenvalues $\ge c$” with the mean held fixed, the property that the log-likelihood does not decrease is preserved). Convergence is declared when the increase in the log-likelihood is $\le10^{-10}(\abs{\ln p}+1)$.
  • ① (k-means): assignment to the nearest mean and update of the means. The vertical axis shows the objective function $J$ (a quantity different from the log-likelihood).
  • ② (two dimensions): For the sample covariance matrix $\bm{S}$ (with the factor $1/N$), the simulator plots, as functions of the angle, the variance of the projection onto the direction $\bm{u}$, $\bm{u}^{\tp}\bm{S}\bm{u}$, and the reconstruction error $\tr\bm{S}-\bm{u}^{\tp}\bm{S}\bm{u}$, and finds the principal axis.
  • ② (spectra, 60 spectra × 200 points): From the SVD of the centered data, it obtains the eigenvalues $\lambda_i=s_i^{2}/N$, the loadings, and the scores, and displays the reconstruction with $k$ components and the mean reconstruction error (= the sum of the discarded eigenvalues). As a guide to the range of the eigenvalues for pure noise, it draws a band $\sigma^{2}(\sqrt{D}\mp\sqrt{N})^{2}/N$ (an approximation for large matrices).

D.8.3 Input ranges, upper limits, and random numbers

  • ①: five data sets (separated / overlapping / elongated / different sizes / degenerate example; synthetic data for teaching purposes; dimensionless), $K$ from 1 to 6 (default 2), $N$ from 10 to 300 (150), variance floor $c$ from $10^{-4}$ to 1 (0.010), and up to 1000 iterations.
  • ②: in two dimensions, $N$ from 2 to 300 (100), a scale factor from 0.1 to 10 that changes the unit of $x_2$, and a switch for standardization. For the spectra, 2 or 3 pure components, a noise standard deviation from 0 to 0.1 (0.020), and a number of reconstruction components $k$ from 0 to 10.
  • There are two seeds: the data seed (default 20261113) and the initial-value seed (default 1; it selects the data points used as the initial means). For the initial values, the first $K$ points of the permuted data points are used as the means, with $\bm{\Sigma}_k=(\tr\bm{S}/2)\bm{I}$ and $\pi_k=1/K$.

D.8.4 Simplifications

  • ① is two-dimensional only. The initial values are randomly chosen data points (k-means++ and the like are not used). $K$ is chosen by hand.
  • In the degenerate example, to make the degeneracy reliably visible, the initial mean of the last component is placed at an isolated point (stated explicitly on the screen). Degeneracy does not occur for every initial value.
  • The spectra include neither baselines nor peak shifts, and the noise is uniform Gaussian noise.

D.8.5 Conditions for instability and the behavior of the simulator

  • Without the variance floor, degeneration onto a single point (or a line) can make the log-likelihood grow without an upper limit. An update that would make the smallest eigenvalue of a covariance less than $10^{-10}$ is not adopted, and the simulator displays “Stopped (degenerate)” together with the reason (in the degenerate example with $K=2$, it stops after −462.35 → −307.53 → −301.11).
  • For a component whose sum of responsibilities $N_k$ is almost 0, the previous values are kept and a caution is displayed (the same applies to empty components in k-means). Local minima exist (the result changes with the initial-value seed).
  • In two-dimensional PCA, the principal axis is hard to determine when the two eigenvalues are nearly equal. For $N=2$, the second eigenvalue is 0 (a caution is displayed).
  • The values on the screen and those from Node.js were treated as agreeing to the fifth digit, because of a 1 ulp difference in the Gaussian random numbers.

D.9.2 What is computed

  • The targets are one-dimensional, and there are three kinds that can be normalized by numerical integration on a grid: a skewed unimodal distribution $\tilde p(x)=x^{a-1}(1-x)^{b-1}$ (Beta type, $Z=B(a,b)$), a bimodal distribution $\tilde p(x)=w\,e^{-(x+d/2)^{2}/2}+(1-w)\,e^{-(x-d/2)^{2}/2}$, and a double well $\tilde p(x)=\exp[-b(x^{2}-1)^{2}]$ ($b=E_b/(k_{\mathrm B}T)$). Here $p(x)=\tilde p(x)/Z$ ($Z$ corresponds to the marginal likelihood $p(\data)$ of Chapter 20).
  • ①: With the approximating distribution $q(x)=\Normal(x\mid m,s^{2})$, the simulator compares the Laplace approximation (mode $x^{*}$, curvature $\Lambda=-(\dd^{2}/\dd x^{2})\ln\tilde p\,\vert_{x^{*}}$, $q=\Normal(x\mid x^{*},\Lambda^{-1})$, $\ln Z\approx\ln\tilde p(x^{*})+\tfrac12\ln(2\pi/\Lambda)$; the screen also displays $\Lambda$), the Gaussian distribution that minimizes $\KL(q\,\|\,p)$ (Nelder–Mead method; the destination depends on the initial value), and the Gaussian distribution that minimizes $\KL(p\,\|\,q)$ (matching of the mean and variance), and displays the KL divergence in both directions, the mean and variance, and $\ELBO(q)=\Ex_q[\ln\tilde p]-\Ex_q[\ln q]$ together with $\ln Z=\ELBO+\KL(q\,\|\,p)$. The integrals use Simpson’s rule with 4000 intervals (for the Beta type, with the change of variables $x=u^{3}(10-15u+6u^{2})$), and the expectations over $q$ are computed on $m\pm12s$ with 2000 intervals.
  • ②: The Metropolis–Hastings algorithm with the Gaussian random-walk proposal $x'=x+s\varepsilon$ (acceptance probability $\min(1,\tilde p(x')/\tilde p(x))$; accept when $u\lt\min(1,r)$). One to four chains. It displays the acceptance rate (shown to three significant digits), the integrated autocorrelation time $\tau_{\mathrm{int}}=1+2\sum_{k=1}^{k_c}\rho_k$ (the cutoff $k_c$ is Sokal’s automatic window; the screen also shows it as $\tau_{\mathrm{int}}$, a quantity distinct from the temperature $\tau$ of Chapter 26), the effective sample size $S/\tau_{\mathrm{int}}$, the Monte Carlo standard error of the mean, and the split-$\hat{R}$ (each chain divided into its first and second halves; no rank normalization). The autocorrelation is computed by FFT. Inside the collapsible panel, the transition matrix of the Metropolis algorithm for a three-state discrete distribution is displayed as fractions.

D.9.3 Input ranges, upper limits, and random numbers

  • ① (no random numbers): Beta $a,b$ from 1.5 to 20 (default 3, 9); for the bimodal distribution, the left weight $w$ from 0.05 to 0.95 (0.60) and the separation $d$ from 0 to 8 (6.0); for the double well, the barrier $b$ from 0.25 to 15 (3.00).
  • ②: proposal width $s$ from 0.01 to 10 (logarithmic scale; default 0.300), 1 to 4 chains (4), initial values scattered / all at the same point, burn-in 0 / 10 / 25 / 50 % (10 %), and up to 20,000 steps per chain. The default target is the double well with $b=2$.
  • The default seed is 20261112. Chain $k$ (0–3) uses the random-number sequence of seed $+7919k$, drawing one number at a time in the order $\varepsilon$ → $u$ in each step. Even if the number of chains is changed, the sequence of chain 1 stays the same.

D.9.4 Simplifications

  • Only one-dimensional targets for which $Z$ can be obtained by numerical integration on a grid. $q$ is only a one-dimensional Gaussian distribution.
  • For a Beta-type target, a Gaussian $q$ puts probability on $x\lt0$ and $x\gt1$, so $\KL(q\,\|\,p)=\infty$. Therefore, for the minimization of $\KL(q\,\|\,p)$ and the ELBO bar, a “Gaussian distribution truncated to $0\lt x\lt1$ and normalized” is used, and the table lists both ∞ and the truncated value ($\KL(p\,\|\,q)$ and the Laplace approximation are not truncated).
  • MCMC uses only the random-walk proposal. $\hat{R}$ is the split-$\hat{R}$ without rank normalization.

D.9.5 Conditions for instability and the behavior of the simulator

  • The minimization of $\KL(q\,\|\,p)$ has local minima. If the Nelder–Mead method does not converge within 4000 iterations, the simulator says so. When the Beta $a,b$ are close to 1.5, the Laplace approximation is far off.
  • If a chain is short, the cutoff $k_c$ reaches half the sequence length and the simulator displays “sequence too short” ($\tau_{\mathrm{int}}$, the effective sample size, and $\hat{R}$ are not reliable). A proposal outside the support is always rejected.
  • If the barrier is high, a chain cannot leave one of the wells. In the barrier example (double well $b=12$, $s=0.3$, 4 chains, 2000 steps), none of the four chains leaves the well it started in, and $\hat{R}=9.898$. When the initial values are set to “all at the same point,” $\hat{R}=1.003$ yet the overall mean is −0.98 (the true value is 0), so even $\hat{R}\approx1$ does not guarantee convergence.
  • For NaN or ∞, the computation is stopped and the reason is displayed.

D.10.2 What is computed

  • ①: Two hidden states (1 = normal, 2 = degraded), the initial distribution $\pi_i$, the transition matrix $A_{ij}=p(z_t=j\mid z_{t-1}=i)$, and the emission probability $B_{jv}$ (three discrete values: low, medium, high) or a Gaussian output (mean 0 for normal, mean $\Delta$ for degraded, standard deviation 1). The scaled forward computation $$\begin{aligned}c_t&=p(x_t\mid x_{1:t-1}),\\ \hat\alpha_t(j)&=p(z_t=j\mid x_{1:t}),\\ \ln p(x_{1:T})&=\sum_{t=1}^{T}\ln c_t\end{aligned}$$ gives the filtering and the likelihood; the backward computation and $\gamma_t=\hat\alpha_t\hat\beta_t$ give the smoothing; and the Viterbi algorithm carried out with logarithms ($\omega_t(j)=\max_{z_{1:t-1}}p(x_{1:t},z_{1:t-1},z_t=j)$, with ties broken in favor of the state with the smaller number) gives the most probable sequence of states. A version computed in the logarithmic domain is calculated at the same time, and its difference from the scaled version is displayed.
  • In hand-calculation mode ($T=3$), the simulator lays out the unnormalized $\alpha_t(j)=p(x_{1:t},z_t=j)$, $\beta_t(j)=p(x_{t+1:T}\mid z_t=j)$, $\gamma_t$, $\omega_t$, the backpointer $\psi_t$, and a table of the full enumeration of the eight state sequences.
  • ②: The Kalman filter for a one-dimensional random walk $z_t=z_{t-1}+\sqrt{q}\,\varepsilon_t$ with observation $x_t=z_t+\sqrt{r}\,\eta_t$: $$\begin{aligned}P_{t\mid t-1}&=P_{t-1}+q\quad(t\ge2),\\ K_t&=\frac{P_{t\mid t-1}}{P_{t\mid t-1}+r},\\ \mu_t&=\mu_{t\mid t-1}+K_t(x_t-\mu_{t\mid t-1}),\\ P_t&=(1-K_t)P_{t\mid t-1}.\end{aligned}$$ The convention is that the prediction at $t=1$ is $\mu_{1\mid0}=\mu_0=0$, $P_{1\mid0}=P_0=1$ ($q$ is not added). At a time step where the observation is missing, no update is made and $P_t$ grows by $q$ each step. The steady-state values $K_\infty$ and $P_\infty$ are also displayed.

D.10.4 Simplifications

  • There are two states, and $A$ and $B$ do not depend on the time step. The parameters are treated as known, and learning (the Baum–Welch algorithm) is not covered. The estimation uses the same parameters as the data generation (only for the Kalman filter can $q,r$ be set separately). The standard deviation of the Gaussian output is fixed at 1.
  • The Kalman filter covers only the one-dimensional random walk, and there is no smoothing (RTS). $\mu_0=0$ and $P_0=1$ are fixed.

Caution: Attention weights are not necessarily the reason for a decision

The attention weights shown on the screen are the proportions in which each position gathers information from the other positions, and they are intermediate quantities of the computation. You must not read a position with a large weight as “the reason the model decided so.” This caution is also written directly below the weight diagram on the screen.

D.11.3 What is computed

  • ①: From $\bm{X}\in\R^{T\times d_{\mathrm{model}}}$, with the sequence arranged in rows, the simulator forms $\bm{Q}=\bm{X}\bm{W}_Q$, $\bm{K}=\bm{X}\bm{W}_K$, $\bm{V}=\bm{X}\bm{W}_V$, and displays $$\begin{aligned}&\mathrm{Attention}(\bm{Q},\bm{K},\bm{V})\\ &=\softmax\!\left(\frac{\bm{Q}\bm{K}^{\tp}}{\sqrt{d_k}}+\bm{M}\right)\bm{V}\end{aligned}$$ stage by stage (the softmax is taken along the columns in each row; the causal mask is $M_{ij}=-\infty\ (j\gt i)$). The result of the softmax is the attention weight $A_{ij}$ (the proportion in which position $i$ gathers from position $j$). You can switch between dividing and not dividing by $\sqrt{d_k}$ and turn the mask on and off, and the sum of the weights in each row (= 1) is displayed.
  • ②: The forward propagation is computed in double precision inside the browser: embedding + position embedding → two layers (LayerNorm → causal self-attention with two heads → residual, LayerNorm → FFN → residual) → final LayerNorm → product with the transpose of the embedding matrix, which gives the logit $\bm{o}_t\in\R^{67}$ (the logit at position $t$ gives the distribution of the next token under the condition $x_{\le t}$). The next-token distribution is built in the following order: divide the logits by the temperature $\tau$ and apply the softmax (computed by subtracting the maximum); top-k (the $k$ largest); top-p (accumulate the renormalized probabilities in descending order and keep the entries up to the position where the cumulative sum reaches $p$ or more); and renormalize what remains. For sampling, one uniform random number is drawn, the probabilities are accumulated in descending order, and the first token at which the cumulative sum exceeds that number is chosen. The log probability and perplexity of the generated sequence are displayed, with the screen stating which distribution they refer to (the model itself at $\tau=1$, or the distribution actually used).
  • The generated sentences are classified, by comparison with the table and the patterns from which the training data were made, as “correct,” “wrong (contradicts the table),” “not supported by the training data,” and “does not fit a pattern”; a sequence without a period before <eos> is regarded as “incomplete” and is not classified.

D.11.4 Input ranges, upper limits, random numbers, and training conditions

  • ①: $T$ 3–5, $d_{\mathrm{model}}$ 2–4, matrix values −5 to 5 (in steps of 0.5; values out of range are clipped). Five presets.
  • ②: The context is up to 24 tokens (beyond that, the generation button is disabled). $\tau$ 0.05–3 (in steps of 0.05), top-k 0–67 (0 means no restriction), top-p 0.05–1. Fourteen context presets. The default sampling seed is 20261112 (one uniform random number per token; none is drawn for greedy decoding or when only one word remains).
  • Training conditions (record): NumPy random numbers (seed 20261112) were used to create the training data. The number of sentences per material follows three frequency tiers (frequent 1000, medium 100, infrequent 8), and each fact of a material in the infrequent tier appears in training exactly once. AdamW (learning rate $3\times10^{-3}$, warmup for 100 steps and then cosine down to 0, weight decay 0.01), minibatches of 32 rows × 24 tokens, 1500 steps (about 20 passes over the training data), seed 1, CPU, single precision, training time 14.0 s.
  • Tuning of the training: in the first configuration the number of factual errors was 0, so the proportion of the infrequent tier was lowered and the number of passes over the data was reduced, giving the present configuration. All 12 configurations that were tried are recorded, and the final configuration was adopted after the training seed had been fixed at 1 (before the results for seeds 2 and 3 were seen).

D.11.5 Simplifications

  • ① has one head, $d_k=d_v=d_{\mathrm{model}}$, and no bias and no $\bm{W}_O$.
  • ② has a vocabulary of 67, a context length of 24, and word-level tokens (not subwords). The training data are only synthetic sentences, and there are only 8 sentence patterns. The classification targets only sentences that match one of the 8 patterns exactly.

D.11.6 Conditions for instability and the behavior of the simulator

  • In ①, setting the inputs to ±5 makes the scores large and the softmax saturates (the maximum is subtracted in the computation, so the numbers do not overflow).
  • In ②, a small $\tau$ gives the same result as greedy decoding, and a large one increases the sentences that do not fit a pattern. In a context where the top probabilities are close, a correct sentence and a wrong one swap places depending on the seed.
  • For infrequent facts, errors with high probability appear (for example, after “mercury is at room temperature” the word “solid” with 0.998). A high probability does not mean being correct.

D.12 Summary of What Was Not Checked and Limitations

D.12.1 Environments not checked

  • The only environment in which the screens were checked is headless Chrome (desktop version). The widths were 390, 768, and 1280 px (S10 also at 310 and 352 px).
  • We have not checked browsers other than Chrome (Safari, Firefox, etc.). In particular, the display of MathML (bold, script letters, left alignment in tables, stretchy parentheses) may differ from browser to browser.
  • We have not checked touch operation on actual smartphones or tablets. The check at 390 px was done by narrowing the width of desktop Chrome.
  • We have not checked reading aloud with screen readers. Keyboard operation was checked with the scripted operations. We have also not checked the display in an environment with prefers-reduced-motion (the setting that reduces motion; no simulator is built to move automatically).
  • When the files were opened directly without starting a server (file://), we confirmed that there are no console errors immediately after opening in all 10 simulators. Only S09 and S10 were taken through the scripted operations over file:// (Table D.3).
  • The tracking of the frame height when a simulator is embedded in a chapter is not included in the per-simulator screen checks. The display at narrow widths corresponding to the width of the chapter frame was checked only for S10 (310 and 352 px; the equations fit inside the frame) and S09 (330 px; the equations scroll sideways inside the equation field).

D.12.2 Known limitations

  • 1 ulp differences in random numbers: Gaussian random numbers may differ in the last 1 ulp between Node.js and Chrome (D.1.3). This is not usually visible in the displayed digits, but the iteration count of an ill-conditioned SVM changes slightly with the environment (7,614 and 7,583).
  • Values of the logarithmic-scale sliders: $\gamma$ and $C$ in S04 move in steps of 0.05 in $\log_{10}$, so they do not land exactly on round values (the displayed 20.0 is 19.953, 0.0501 is $10^{-1.3}$, and 5.01 is $10^{0.7}$). $\eta$ cannot be set to 0.3 and gives 0.32. The right end of $\eta$ in S05 is 2.5 ($10^{0.4}$) and does not reach 3.16. $\ell$ in S06 is 0.1995 at the 0.2 position and 5.012 at the 5 position. The numerical values in the main text are written as the values that actually appear on the screen.
  • Number of samples in S01: the upper limit for the samples in ① is 10000 (the $n=20000$ of the test is outside the screen).
  • Number of support vectors in S04: because of the SMO stopping tolerance $\varepsilon=10^{-3}$, it may differ by one from the exact solution (D.5.5).
  • Tail precision in S06: beyond $z\approx-20$, the relative error of $\Phi(z)$ is about 0.4 %. In a setting where EI is extremely small everywhere, the chosen point is determined by rounding (D.7.5).
  • Baseline value in S03: a simplification is made in which a fixed 88 % is subtracted from the target value and the penalty is applied to all coefficients, including the intercept (D.4.4).
  • Loss convention in S04: the loss is a sum of cross-entropies, and the stable learning rate depends on $N$. S05 uses the mean loss (this corresponds to the differences in loss conventions among Chapters 7, 8, 9, 14, and 15).
  • Mean function in S06: the computation uses the formula that includes a constant $m$ (default $\bar{y}$). The recommended point is the point with the largest observed value, and because of noise the simple regret may increase with the number of evaluations.
  • Degenerate example in S07: the degeneracy is produced by placing the initial mean of the last component at an isolated point.
  • Beta-type target in S08: the minimization of $\KL(q\,\|\,p)$ and the ELBO are computed with a truncated Gaussian distribution. $\hat{R}$ is the split-$\hat{R}$ without rank normalization.
  • Kalman filter in S09: the convention is not to add $q$ in the prediction at $t=1$. The numerical values do not agree with the notation that sets $P_{1\mid0}=P_0+q$.
  • S10: ② is not GPT, and the evaluation values are not the error rates of an actual GPT. The attention weights are not necessarily the reasons for a decision.

D.12.3 Beyond the range checked

  • The numerical tests were carried out within the ranges of parameter sets and numbers of cases written in each table. We did not try every combination of the sliders. In particular, for ill-conditioned computations near the boundaries (high degrees, large $C$, long $\ell$ with small $\sigma$, and so on), the agreement with the reference computation also worsens in accordance with the condition number.
  • The statistical checks were done only once with a fixed seed, and they are tests at a significance level of about 0.1 %. Passing a statistical check is not a proof that the generator or the algorithm is correct.
  • Among the numerical values of the chapters in the main text, the figures and tables made with the same random-number sequence as the simulators (mulberry32) agree with the simulator screens, but the figures and tables made separately with NumPy random numbers (such as the comparison in Chapter 13) use a different random-number sequence, so their numerical values do not agree (this is stated in the explanation of the figures in each chapter).
  • The evaluation of the trained model (S10 ②) gives values for this small model and this synthetic sentence, and it does not apply to other models or data.
